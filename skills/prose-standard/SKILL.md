# VoidCube 文案规范

文字只保留读者完成任务需要的事实：前置条件、行为、约束、失败状态、验证方式和所有权。用当前状态描述系统，删除审查对话、实现过程旁白、重复规则和无证据的未来计划。

## 判断标准

- 每个句子表达完整命题，术语对应当前代码或正式文档中的字段、命令和状态。
- 错误、警告和用户可见文本说明下一步行动，不把内部堆栈或推测当成事实。
- 注释解释非显而易见的约束、竞态、平台差异或为什么测试需要特殊夹具；不要逐行复述代码。
- 技能描述准确指出触发场景、边界和依赖，避免承诺当前工具无法执行的操作。
- 把“曾经/后来/这个 PR/审查认为”等过程视角改写为当前行为；保留有明确 issue 或历史证据价值的引用。

修改后检查代码、测试和文档是否仍表达同一事实，并运行相应契约测试。涉及技能时运行 registry 测试和完整门禁。
