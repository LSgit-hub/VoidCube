# VoidCube 代码审查

先确认变更的真实范围，再阅读相关实现、调用方、测试和根目录 `AGENTS.md`。审查重点按风险排序：错误行为、数据或资源所有权、鉴权与输入安全、生命周期和并发、用户可见协议，最后才是风格问题。

## 必查项目

- 配置、默认值、错误码、事件、工具 schema 和公开行为是否与文档及调用方一致。
- 新增注册、插件、技能或资源是否有卸载、清理、重复加载和失败回滚路径。
- 代码是否引入了只为旧实现服务的参数、兼容分支或重复状态；如果没有当前消费者，应删除。
- Windows 和 POSIX 的路径、编码、进程、文件锁、时区及信号语义是否有明确处理。
- 测试是否通过真实入口证明失败状态、外部副作用和清理完成，而不是只复述实现。
- 技能中的命令、相对链接、依赖和工具名称是否存在于当前 VoidCube；不能把外部项目规则当成本项目规则。

## 证据

按变更范围运行目标测试；涉及 `src/`、`Mem/src/`、技能、协议或打包时运行 `scripts/run_ci_tests.py`，并运行相关契约测试。没有执行的检查不得写成通过。发现问题时给出文件、行号、触发条件、影响和最小修复方向。
