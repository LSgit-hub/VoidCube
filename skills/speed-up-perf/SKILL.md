# VoidCube 性能优化

先定义用户可感知的路径、输入规模、资源约束和停止标准。区分本地计算、磁盘/SQLite、进程启动、网络和模型延迟；不要用单次空载时间推断整体体验。

## 方法

1. 找到真实入口和当前基线，确认测量不会读取凭据或改变持久状态。
2. 用 `time.perf_counter()`、项目已有测试和可审查的样本测量，记录环境、规模、热/冷缓存和方差。
3. 优先修复重复 I/O、无效扫描、过早加载、锁竞争和不必要的序列化；保持所有权与错误语义不变。
4. 为可疑优化添加能在回归时失败的行为或性能测试，不用放宽阈值来掩盖抖动。

技能 registry 的热路径应遵守现有耗时测试；技能或源码改动完成后按 `AGENTS.md` 运行完整门禁。报告基线、改后结果、测量边界和未覆盖的外部延迟。
