# 测试可靠性

测试必须在仓库支持的 Python 3.14 与 Windows 环境中验证真实行为。先阅读仓库的 `docs/testing.md` 和根目录 `AGENTS.md`，再选择与变更范围匹配的检查。

## 资源与状态

- 每个测试使用 `tmp_path` 创建独立目录、数据库、会话和输出文件，不使用可预测的共享路径。
- 网络服务绑定 `127.0.0.1:0`，等待真实监听信号后再读取端口；不要先扫描空闲端口再延迟绑定。
- 修改环境变量、工作目录、全局注册表、时钟或 monkeypatch 后，立即注册 `try/finally` 清理，并恢复“原本不存在”的状态。
- Windows 文件、进程和端口的释放可能晚于 `close()` 或 `kill()`；等待可观察的退出、关闭或完成信号。
- 固定 sleep 只能作为已确认状态后的展示等待，不能用来证明初始化或清理完成。

## 证明回归

让无效输入或错误状态通过真实入口先失败，再由修复后的断言证明回归消失。检查外部文件、日志、事件、退出码或数据库状态，不只检查被测对象自己的返回值。涉及并发时用 barrier 或事件确定性地安排重叠；重复运行不能替代竞态测试。

## 验证

先运行受影响的 pytest 用例；涉及 `src/`、`Mem/src/`、技能或协议时，按仓库规则运行完整门禁：

```powershell
.venv\Scripts\python.exe scripts/run_ci_tests.py
```

报告确切命令、通过数、跳过数和仍存在的环境限制。不要用放宽断言、吞掉异常、无理由增加超时或把整个测试套件串行化来掩盖问题。
