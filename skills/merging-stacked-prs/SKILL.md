# 合并依赖 PR

先建立从底层到顶层的依赖图，确认每个 PR 的 base、head、CI 状态和审查结论。每层只包含自己的变更，避免通过手工合并把未审查的上层提交带入底层 PR。

## 流程

1. 用 `gh pr view`、`gh pr checks` 和 `git log --graph` 核对远端状态；没有 `gh` 或权限时只提供命令和审查报告。
2. 从底层 PR 开始验证，合并后重新确认上层 PR 的 base、diff 和 CI，不假设分支会自动保持正确。
3. 发生冲突时先保存证据和受影响范围，按仓库规则解决并重新运行验证；不要删除或重建远端分支来绕过冲突。
4. 合并前确认工作树、目标分支、PR 顺序和保护规则。合并操作属于外部副作用，只有用户明确要求时执行。

报告依赖图、每层的验证命令、CI 结果、冲突和剩余风险。
