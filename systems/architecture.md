# VoidCube 服务化架构说明

`systems/` 目录的当前服务化架构统一定义在：

- [docs/voidcube架构基线.md](../docs/voidcube架构基线.md)

这份入口文件只保留两点说明：

## 1. 当前目录的职责

`systems/` 用于承载 VoidCube 的服务化运行链路，包括：

- 内部网关
- 记忆服务
- 监督治理
- Execution 受控执行面与身体运行时

## 2. 架构约束

`systems/` 必须遵守 `docs/voidcube架构基线.md` 的现行边界：

- 监督者是裁决者，不是长期执行器
- Agent 可以持有可恢复的会话、消息游标和临时上下文，但不拥有长期身份、治理裁决或跨会话事实真相
- 记忆服务承担长期持久化
- 不存在独立的“自学系统”运行服务；`self_learning` 任务由监督者生成，由 API-A 自主执行面 pull 执行，成果进入 Mem
- Supervisor 启动后自主链路门控保持关闭；`/auto` 临时启用内生驱动、治理复核和 API-A 自主执行组件，`/auto-q` 临时停用
- 用户链路和自主链路必须互不抢占、互不覆盖；Web 监控只作为 API-B 观测面

代码实现与该文档冲突时视为架构缺陷，不得继续扩张冲突职责。
