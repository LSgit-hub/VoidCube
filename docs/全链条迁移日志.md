# 全链条迁移日志：自主链路收口过程

更新日期：2026-07-07

> 本文档只保留“为什么会出现这些旧术语、它们如何退场”的迁移脉络。当前有效基线请以 [全链条报告.md](./全链条报告.md) 与 [voidcube架构基线.md](./voidcube架构基线.md) 为准。

## 1. 迁移目标

2026-07-03 到 2026-07-07 这一轮收口的核心目标只有两个：

- 把 VoidCube 从“旧队列管理台 / 自提升模式”叙事，收口到“自主链路 + 用户链路”双链路语义。
- 把 Web 小屋、最小 dashboard 和主 CLI 的自主观察面，统一收口到同一棵 `autonomous_observation` 状态树。

## 2. 关键迁移阶段

### 2.1 主语从 `self_evolution / queue / auto-mode` 收口到 `autonomous_chain`

- 外部治理路由从历史 `/self-evolution/*` 收口到 `/autonomous-chain/*`。
- Supervisor 内部 orchestration 命名、Gateway 活动字段、trace source、runtime 调度命名同步转向 `autonomous_chain`。
- `/auto` 被重新限定为“自主链路的临时启停开关”，而不是主 CLI 的一种模式。

### 2.2 Web 小屋从旧队列管理台收口到自主链路观测面

- 顶层 `queue_layout`、`panels`、`tasks`、`drive_candidates` 等旧展示主语陆续退场。
- Web 小屋内部主叙事从任务墙改成“自主链路闭环 + 闭环分段观察 + trace 钻取”。
- 房间动画、粒子、Dock、场景骨架保留不变，变化集中在状态协议和展示语义。

### 2.3 状态协议从展示镜像层收口到单树读模型

- `autonomous_observation.queue.sections/headline` 收口为 `autonomous_observation.chain.segments/headline`。
- `autonomous_observation.api_b / api_a / mem / reread` 顶层兼容镜像删除。
- `autonomous_observation.presentation` 展示镜像层删除。
- 当前主读模型固定为：
  - `board`
  - `chain`
  - `loop`
  - `runtime`
  - `counts`

### 2.4 Web 小屋的 segment 语义从“任务切片”收口到“链路阶段”

- 当前有效顺序为 `api_b_candidates -> api_b_backlog -> api_a_ready -> mem_recent`。
- 未被 API-B 放行的 `self_learning / body_improvement` 不再伪装成 API-A 待执行，而是留在 `api_b_backlog`。
- 只有真正进入 API-A 拉取阶段的任务才进入 `api_a_ready`。

### 2.5 CLI / dashboard 从旧兼容读取收口到 `chain.segments + loop.stage_cards + loop.rail_entries`

- 主 CLI 自主执行面不再回退读取旧 `panels.learning`、`api_a.current/pending` 或历史展示层别名。
- 最小 dashboard 不再回退到旧治理队列视角，缺少观测板时只显示空态。
- 自主链路的“已放行待认领 / 他处执行中 / 治理段待放行 / 等待放行”等解释，现优先回到 `loop.stage_cards[stage_key=api_a_execution]` 与 `loop.rail_entries` 自身字段承载。
- `loop.stages` 在当前基线下已退到历史兼容镜像，只允许留在显式 compat helper/fallback 与专项回归中，不再作为现役主协议。

### 2.6 自主执行面从主 CLI 体内持续下沉

- 已拆出的模块包括：
  - `VoidCube_cli/autonomous_observation.py`
  - `VoidCube_cli/autonomous_panel.py`
  - `VoidCube_cli/autonomous_gate.py`
  - `VoidCube_cli/autonomous_presence.py`
  - `VoidCube_cli/autonomous_events.py`
  - `VoidCube_cli/autonomous_runtime_host.py`
  - `VoidCube_cli/autonomous_status_host.py`
- 主 CLI 逐步退回“用户链路入口 + 自主链路薄桥接壳”的角色。

### 2.7 历史 `self_learning` 服务化叙事降级

- `systems/self_learning/` 被重新定义为历史学习结论兼容层，而不是独立执行服务。
- `SelfLearningConclusionStore` 的职责被限定为历史结论记录与兼容 payload builder。
- 学习任务真实执行路径固定为：Supervisor 规划 -> API-A pull -> Mem 写回 -> Supervisor 再读取。

### 2.8 身体改进与身体切换语义彻底拆开

- `body_improvement` 继续属于创造类自主任务。
- `body_switch` 保持为独立裁决与执行链，不由任务列表驱动。
- Governor、用户同意门和执行器机械流程边界因此得以保持清晰。

## 3. 已退场的历史术语

以下术语仍可能在旧测试、旧提交或旧笔记里出现，但现在都不应再被当成当前主协议：

- `task_queue`
- `queue.sections`
- `queue.headline`
- `queue_preview`
- `queue_headline`
- `watch_groups`
- `presentation`
- `/self-evolution/*` 对外治理入口
- “主 CLI auto mode”

## 4. 使用建议

- 讨论当前实现时，优先使用“自主链路 / 用户链路”。
- 讨论状态协议时，优先使用 `board / chain / loop / runtime / counts`。
- 讨论 Web 小屋时，优先使用“API-B 主视角的自主链路观测面”。
- 若必须追溯旧术语来源，再回看本文档，而不是把这些历史别名继续带回主设计文档。
