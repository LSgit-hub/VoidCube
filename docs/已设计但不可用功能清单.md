这些工具位于 [VoidCube_cli/tools/](../VoidCube_cli/tools/) 下，只定义了 JSON Schema，**没有任何执行 handler**。它们通过 `VoidCube_cli/plugins.py` 的 `PluginManager` 注册，但 `PluginManager` 没有 `dispatch()` 方法，无法执行任何工具。

| 工具名 | Schema 文件 | Handler？ | 在 LLM 定义中出现？ |
|---|---|---|---|
| `git_manage` | [VoidCube_cli/tools/git_tool.py](../VoidCube_cli/tools/git_tool.py) | 无 | 从不出现 |

| `vision_analyze` | [VoidCube_cli/tools/vision_tool.py](../VoidCube_cli/tools/vision_tool.py) | 无 | 从不出现 |
| `append_file` | [VoidCube_cli/tools/append_file_tool.py](../VoidCube_cli/tools/append_file_tool.py) | 无 | 从不出现 |

**额外问题**：`_LEGACY_TOOLSET_MAP` 中的 `vision_tools: ['vision_analyze']` 也引用了 `vision_analyze`，但主 registry 中不存在此工具，是一个死引用。

**修复方式**：

- 方案B：从 `VoidCube_cli/tools/` 和 `VoidCube_cli/plugins.py` 中删除这些死代码

## 四、Import 断裂

### MCP `create_custom_toolset` 不存在

**位置**：[tools/mcp_tool.py:1746](../tools/mcp_tool.py)

```python
from tools.toolsets import create_custom_toolset, TOOLSETS
```

`create_custom_toolset` 函数**在 `tools/toolsets.py` 中根本不存在**。导入会抛出 `ImportError`。虽然被 `asyncio.gather(return_exceptions=True)` 静默吞掉，但会导致每个 MCP server 的 `_register_server_tools()` 调用失败。MCP 工具通过另一个路径（`_sync_mcp_toolsets`）仍可部分工作。
