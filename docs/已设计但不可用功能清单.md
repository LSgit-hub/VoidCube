## 二、仅有 Schema 无实现的插件工具（5个）

这些工具位于 [VoidCube_cli/tools/](../VoidCube_cli/tools/) 下，只定义了 JSON Schema，**没有任何执行 handler**。它们通过 `VoidCube_cli/plugins.py` 的 `PluginManager` 注册，但 `PluginManager` 没有 `dispatch()` 方法，无法执行任何工具。

| 工具名 | Schema 文件 | Handler？ | 在 LLM 定义中出现？ |
|---|---|---|---|
| `git_manage` | [VoidCube_cli/tools/git_tool.py](../VoidCube_cli/tools/git_tool.py) | 无 | 从不出现 |
| `http_request` | [VoidCube_cli/tools/http_tool.py](../VoidCube_cli/tools/http_tool.py) | 无 | 从不出现 |
| `browser` | [VoidCube_cli/tools/browser_tool.py](../VoidCube_cli/tools/browser_tool.py) | 无 | 从不出现 |
| `vision_analyze` | [tools/vision_tools.py](../tools/vision_tools.py) | 有，统一 auxiliary vision 路由 | 已进入 `vision` toolset |
| `append_file` | [VoidCube_cli/tools/append_file_tool.py](../VoidCube_cli/tools/append_file_tool.py) | 无 | 从不出现 |

**当前结论**：原清单把旧插件 schema 当成了唯一实现。现在正式实现位于 `tools/vision_tools.py`，由 `tools/model_tools.py` 发现并注册到 `vision` toolset；设计目的已经接回主链。

**修复方式**：
- 方案A：为每个工具补充 handler 实现，接入 `tools/registry.py`
- 方案B：从 `VoidCube_cli/tools/` 和 `VoidCube_cli/plugins.py` 中删除这些死代码
