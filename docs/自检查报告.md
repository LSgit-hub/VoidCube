# VoidCube 自检查报告

## 结论

原报告指出的 5 项问题已经完成修复，并已接入自主学习/替身执行链路：

1. 终态收尾、会话持久化和资源清理已闭环。
2. Mem 同步失败会形成可重试的持久化 outbox 状态。
3. 普通文本工具输出增加明确失败模式识别，避免把失败传给模型时伪装成成功。
4. 工具调度路径使用 `Path.resolve(strict=False)`，符号链接别名会进入同一冲突检测空间；解析失败时强制串行。
5. 上下文压缩前会原子持久化结构化 checkpoint；摘要失败时恢复 checkpoint 投影和 action refs，不再只留下静态丢失提示。

## 执行环境风险

原报告在临时沙箱中得到的 `httpx`、`sqlite-vec` 结论不能代表 Windows 宿主环境，现已从主结论中删除。当前项目明确区分：

- Windows 宿主路径，例如 `F:\\...\\VoidCube`；
- Podman/WSL 执行路径 `/workspace`；
- 宿主和执行环境各自的 Git、Python、pytest、Node、npm 可执行文件及版本；
- 依赖声明文件指纹（`requirements*.txt`、`pyproject.toml`、Node 锁文件等）；
- Git HEAD、工作区路径映射、执行后端和验证平台。

`ExecutionEnvironmentManifest` 是内容寻址且不可变的环境证据。Benchmark baseline 和 candidate 必须使用同一份环境清单；环境漂移会直接终止评测。评分策略必须声明所需验证平台，当前 Windows 项目的晋升策略要求 `windows`。Linux Podman 清单只能通过容器范围硬门，不能声称 Windows 宿主测试通过。

替身任务的 Podman 工作树探针现在会验证 `/workspace`、Git HEAD，并采集 Git/Python/pytest/Node/npm 和依赖指纹。Podman 启动失败不得回退到本地执行；任务报告必须携带容器范围环境清单。模型收到的执行提示会列出沙箱工具链，缺少 pytest 或 Node 时必须报告阻塞，不得引用宿主路径替代。

## 主要改动

- `agent/tool_execution.py`、`agent/tool_scheduler.py`：工具失败判定和真实路径冲突。
- `agent/context_compressor.py`、`run_agent.py`：持久化压缩 checkpoint 和会话恢复绑定。
- `systems/evolution_evaluation/models.py`、`executor.py`、`environment.py`：评测环境清单、平台硬门和 baseline/candidate 环境一致性。
- `tools/terminal_tool.py`：Windows linked worktree 到 `/workspace` 的 Git/工具链探针，禁止本地回退。
- `VoidCube_cli/autonomous_executor.py`、`systems/body_registry.py`、监督者治理模块：环境证据随自主任务、改进报告和晋升授权传播。

## 仍需保持的边界

容器验证结果不是 Windows 宿主验证结果。若候选改动涉及 Windows 路径、权限、进程、文件锁或 Node 原生模块，必须在 Windows 宿主重新执行对应 BenchmarkPack，并生成 `validation_scope=host`、`validated_platforms=("windows",)` 的环境证据；否则结果只能观察或拒绝，不能晋升。

## 下一步建议

下一阶段应把“平台敏感测试选择”显式化：根据改动文件和依赖指纹自动选择 Windows 宿主测试、Podman 测试或两者组合，并把每条测试命令及其环境清单 ID 写入可审计证据。这样自进化 Agent 生成测试时会先知道它能在哪个环境运行，测试结果也不会跨环境误归因。
