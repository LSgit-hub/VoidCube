# 自主学习架构改进方案

> 文档状态：第一阶段基础设施、第二阶段 2A/2B/2C 与第三阶段只读影子接入已实现（2026-08-14）。内生驱动现在只消费三类事实并生成不可执行的 shadow task；尚未迁移旧结论存储，也未接入身体改进流程。

核心原则是：三个基础设施彼此独立，只输出不可变、可引用的事实对象；自进化编排器以后只消费这些对象，不反向侵入基础设施。

一、自我认知
建议独立模块：systems/self_cognition/
输出 SelfCognitionSnapshot，每次快照都不可修改：
snapshot_id
body_id、Git commit、配置摘要
代码模块与依赖关系
工具、技能、模型和运行能力清单
测试、启动、记忆、性能健康指标
当前已知缺口和未覆盖区域
采集器版本及内容哈希
它只负责回答“我现在是什么”，不负责判断怎么改。现有 endogenous_self_model.py 应降为该快照的投影消费者，而不是事实来源。
二、外部知识体系
建议独立模块：systems/research_knowledge/
核心对象为 KnowledgeArtifact：
knowledge_id、主题、版本
原子化 claims，而不是一篇大总结
来源 URL、来源类型、抓取时间、发布时间
适用条件、适用模块和目标问题
与已有知识的一致、补充或冲突关系
时效期限、置信度和质量评分
原始研究任务与工具证据引用
知识库只负责“外部有什么理论和证据”。Memory 可以保存它的召回投影，但不能成为唯一事实源；正式知识条目应有独立版本和来源记录。
刚实现的自主学习质量评分应定位为“知识准入质量”，不是“进化效果评分”。
三、对比实验与评分
建议独立模块：systems/evolution_evaluation/
三个核心契约：
BenchmarkPack
ExperimentSpec
ExperimentResult
ExperimentSpec 必须包含：
基线自我认知快照 ID
候选 commit 和候选快照 ID
改进假设
引用的知识条目 ID
目标指标
允许回归范围
固定版本的 BenchmarkPack
基线和候选必须运行完全相同的评测集。评分先做硬门，再算收益：
维度	建议权重
正确性和任务成功率	40%
稳定性和恢复能力	25%
性能、延迟与成本	15%
可维护性	10%
理论与证据支撑	10%


硬门包括测试、进化边界、安全扫描、可启动、可回退和评测可复现。任何硬门失败都不能靠加权总分抵消。
最终结果不是简单的“85 分”，而应包括：
baseline_metrics
candidate_metrics
metric_deltas
regressions
confidence
hard_gate_results
verdict: promote | observe | reject
LLM 可以提出假设、选择知识和解释结果，但不能自行填写测试结果或决定最终分数。
存储边界
建议使用内容寻址的不可变 JSON 记录，配合独立索引：
runtime/evolution-foundation/
├── self-cognition/
│   ├── snapshots/
│   └── index.json
├── knowledge/
│   ├── artifacts/
│   └── index.json
├── evaluation/
│   ├── benchmark-packs/
│   ├── experiments/
│   └── index.json
三个 Repository 互不导入，只通过 ID 引用。统一使用原子写入、schema version 和内容哈希。以后数据量明显增长时，再把 Repository 实现替换为 SQLite，领域契约不变。
建议补充
定义完整链路：认知缺口 -> 知识缺口 -> 可证伪假设 -> 候选变更 -> 对比实验 -> 治理决策 -> 本地适用性证据。
所有评分阈值放入版本化 ScoringPolicy，不要固化一套适用于所有任务的权重。
Web 内容按不可信输入处理，加入来源去重、提示注入隔离、内容摘要哈希、时效复核和撤回机制。
为每个阶段增加退出条件。尤其应增加“影子运行阶段”：系统只生成建议和实验结论，不触发身体改进，用真实数据校准评分阈值。
第二阶段建议拆成 2A 自我认知采集、2B 知识归一化、2C 评测执行器。BenchmarkPack 执行器不是采集器，三条线路也应能独立交付。
增加文档状态、版本、更新时间、已决定事项、待决定事项和阶段检查表，方便长期跟踪。
最重要的三项是：效果与证据分离、实验结果反哺知识适用性、Benchmark 防过拟合。
实施顺序
第一阶段只实现模型、存储、校验和版本规则，不接内生驱动。
第二阶段实现三个采集器：代码自我认知采集、Web 知识归一化、BenchmarkPack 执行。
第三阶段让内生驱动只读这些基础设施，据此生成“补认知、补知识、做实验”三类任务。
第四阶段才允许身体改进使用 ExperimentResult 进入 Governor 和用户同意流程。
旧结论兼容存储、专用提交端点和数据模型已删除。工作区未发现需要迁移的旧结论数据；当前自主学习结果继续由 autonomous-chain 写回历史承载，外部知识和实验结果分别进入独立基础设施。第三阶段影子结果校准已完成；进入第四阶段前需要明确授权 Governor、用户同意和身体改进的接入边界。
