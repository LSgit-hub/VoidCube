# 全链路问题清单

> 当前清单只按最新 `voidcube架构基线.md` 记录，不引用已删除的历史报告。

## 已收口

- 自主链路和用户链路已在主读模型上分开：用户链路走主 CLI / `user_chat`，自主链路走 API-B 判断、API-A 自主执行面、Mem 回流和 API-B 再读取。
- 主 CLI 用户 host 不再 poll、认领或注入自主任务 prompt；`/auto` / `/auto-q` 已收口为本地自主链路观测/执行面的接入与退出提示，不再作为 Supervisor 自主链路主启停门控。
- 嵌入式最小 CLI 组件已成为自主链路专用跟踪展示组件：展示 API-B 模型生成 / 候选 / 判断状态，并在 API-B 转交后由同一组件内的 API-A 自主执行面负责 `supervisor_task` 链路项的 poll / 认领 / 执行 / 回写；默认只在本地 `/auto` 接入且存在 API-B 链路活动或 API-A 执行内容时显示，完全空态隐藏；`VoidCube autonomous` / `VoidCube auto-cli` 仅保留为隔离诊断入口。
- Web 小屋主读模型固定为 `autonomous_observation.read_model_version = 13`，主段为 `api_b_candidates / api_b_judgement / api_a_handoff / mem_recent`。
- Web 小屋不再暴露旧队列管理主协议，不再从 `api_b_backlog / api_a_ready / queue.*` 反推前台分段。
- Web 小屋旧队列管理入口已重新收口为只读观察：前台只读 `chain.segments / loop.stage_cards / board.primary_focus`，旧 `queue_layout / queue.* / review_actions` 不再作为主协议存在。
- Web 小屋前台判断摘要已彻底收口到 `judgement_preview / judgement_hint`；`governance_preview / governance_hint` 旧兼容镜像已从正式读模型移除。
- 替身卡片已能打开简易树形结构图；`body_improvement` 等替身升级任务会优先在具体路径节点显示升级红点，例如 `systems/supervisor/ui_runtime.py`。
- 启动链路口径已统一为 `Gateway → Memory → Supervisor`；Memory 和 Supervisor 依赖 Gateway 完成服务注册。
- 已删除无调用的 `list_governance_backlog_tasks()` / `_governance_backlog_task_summaries()` 函数兼容别名，避免旧 backlog 函数名重新变成读路径主语义。
- 自主链路 runtime store 已能从 MemAI `mem_governance.jsonl` 进行确定性恢复：Supervisor 启动时会在空 store 场景 best-effort 恢复，也可通过 `/autonomous-chain/recover-from-mem` 手动触发。终态事件只恢复为终态投影，不会重新激活历史任务。
- Mem governance 写入侧已补齐恢复关键字段：Governor bridge / body upgrade outcome / self-learning conclusion 会尽量写入 `title`、`summary`、`runtime_task_profile`、`constraints`、`trace_id`、`decision_id`，供 runtime store 恢复使用。
- Supervisor 自主链路默认随 Supervisor 启动进入常驻运行态：`autonomous_chain_start_on_boot=True` 时 review / endogenous-drive 循环不再等待 `/auto`；普通 deactivate 会被跳过，只有显式 `force` 才用于紧急/诊断停机。
- 内生驱动 prompt evidence packet 主协议已收口到 `api_b_judgement_snapshot / api_b_judgement_tasks / api_b_judgement_summary`；`governance_backlog_*` 旧包/旧缓存输入 fallback 已从 prompt-facing packet 移除。
- 内生驱动认知内部压力字段已收口到 `api_b_judgement_count / api_b_judgement_blockage_*`；新 deliberation 输出不再镜像 `governance_backlog_count / governance_backlog_blockage_*`。
- `review_then_backlog` 已只保留为 `_LEGACY_LM_EXECUTION_MODE_ALIASES` 中的旧 LM 输出归一化别名，并由专门 legacy 测试覆盖；当前 prompt 要求和新输出只使用 `review_then_handoff`。
- 身体切换用户同意门已落地：`switch_request` 只会把 probe 通过的槽位置为 `awaiting_user_consent`，`execute_body_upgrade` 返回 `upgrade_awaiting_user_consent`，只有 `/body/switch/consent` 收到显式同意后才触发 `activate_slot` 和 watch window。
- `body_improvement` 转交门控已确定性收口：存在未沉淀的 self-learning 前置项时先 defer；没有足够学习质量证据时 cancel；只有学习质量达到 `body_improvement_min_quality` 后才 approve 给 API-A 自主执行面。
- Mem governance 恢复已支持同一任务跨事件继承：后续终态事件即使只记录执行结果，也不会抹掉早期批准事件中的标题、摘要、trace、运行类型、约束、Git 谱系和证据引用；最后一次原始 `execution_result` 与恢复投影分开保存。
- 替身改进报告已按 `baseline_commit..HEAD` 验证真实 Git 改动，要求 worktree 无未提交/未跟踪变更，并以唯一的 `systems/evolution_boundary.py` 判定改动边界；自报文件列表与 Git 不一致、提交不可验证或越界时直接拒绝评分；相同 task/commit 的重试按幂等结果返回，不重复累加健康分。
- 替身健康评分链路已能消费结构化学习引用、应用时间衰减并把达标建议交给正式 Governor 执行适配器；Governor 签发 probe lease 时由生命周期入口完成 `shell → candidate → probe`。
- 学习结论到替身结构节点的 v1 桥已落地：完成学习回流包含结论/质量/时间，程序按显式路径或受控领域词映射目标；确定性候选与 LM 候选共用映射，LM 不能绕过 worktree、target_paths、learning_refs 和 canonical evolution boundary。改进报告进一步绑定原治理任务及其批准目标子集。
- `approved` 语义已在代码注释、CLI 展示样例和架构基线中收口为历史内部枚举：只表示 API-B 已转交、等待 API-A 接手，不表示执行已发生或 Web 小屋可人工控制执行。
- wheel 构建已收口到 `scripts/build_wheel.py`：构建前定向清理 setuptools 中间目录，构建后双向校验归档文件与当前源码，避免已删除模块因旧 `build/lib` 残留重新进入发行包；Python 模块、Mem prompts 和 CLI locale JSON 均属于校验契约。

## 守住的边界

- Web 小屋只做 API-B 观测，不做用户聊天、不做人工队列控制、不接管主 CLI。
- 主 CLI 是用户链路入口；同一 CLI 内的嵌入式最小 CLI 组件才是 API-A 自主执行面，不允许回退成独立终端作为主路径。
- `api_a_handoff` 只表示“API-B 已转交，等待 API-A 接手”；`running` 任务只进入 API-A 执行观察，不混回 handoff。
- 替身代码改进属于 API-A 自主执行面；身体切换机械流程属于执行器；最终激活新替身必须走用户同意门。
