# 全链路问题清单

> 当前清单只按最新 `voidcube架构基线.md` 记录，不引用已删除的历史报告。

## 已收口

- 自主链路和用户链路已在主读模型上分开：用户链路走主 CLI / `user_chat`，自主链路走 API-B 判断、API-A 自主执行面、Mem 回流和 API-B 再读取。
- 主 CLI 不再默认挂载 API-A 自主执行流程窗口，也不再在 idle 循环里 poll、认领或注入自主任务 prompt；只保留 `/auto` / `/auto-q` 作为自主链路临时启停提示。
- `VoidCube autonomous` / `VoidCube auto-cli` 已成为 API-A 自主执行最小 CLI，负责 `supervisor_task` 链路项的 poll / 认领 / 执行 / 回写；只读 dashboard 仅观察自主执行位，不回退展示用户聊天执行流。
- Web 小屋主读模型固定为 `autonomous_observation.read_model_version = 13`，主段为 `api_b_candidates / api_b_judgement / api_a_handoff / mem_recent`。
- Web 小屋不再暴露旧队列管理主协议，不再从 `api_b_backlog / api_a_ready / queue.*` 反推前台分段。
- Web 小屋旧队列管理入口已重新收口为只读观察：前台只读 `chain.segments / loop.stage_cards / board.primary_focus`，旧 `queue_layout / queue.* / review_actions` 不再作为主协议存在。
- Web 小屋前台判断摘要已迁到 `judgement_preview / judgement_hint`，`governance_preview / governance_hint` 仅作为短期兼容镜像。
- 替身卡片已能打开简易树形结构图；`body_improvement` 等替身升级任务会优先在具体路径节点显示升级红点，例如 `systems/supervisor/ui_runtime.py`。

## 守住的边界

- Web 小屋只做 API-B 观测，不做用户聊天、不做人工队列控制、不接管主 CLI。
- 主 CLI 是用户链路入口，不抢 API-A 自主执行面的最小 CLI 展示，也不承担自主任务执行宿主。
- `api_a_handoff` 只表示“API-B 已转交，等待 API-A 接手”；`running` 任务只进入 API-A 执行观察，不混回 handoff。
- 替身代码改进属于 API-A 自主执行面；身体切换机械流程属于执行器；最终激活新替身应走用户同意门。
