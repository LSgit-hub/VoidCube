# 全链路问题清单

以下不是已确认缺陷，而是从当前代码值得在产品层确认的边界：

1. `InternalGateway` 的会话缓存应始终保持租约/路由元数据，不应承载长期会话真相。
2. `run_agent.py` 仍是大型编排器，新增能力应优先下沉到 `agent/` 的既有责任模块。
3. 端口默认值同时出现在服务启动器和服务配置模型中，修改时应有统一配置测试。
4. `stellar_mode` 已实现进程内原子互斥；若未来要求服务重启后恢复 Auto，必须单独设计用户授权租约，不能直接持久化为启动即 Auto。
5. 三域 Memory、只读跨域提升记录和 Gateway actor 注入已贯穿主存储、召回、删除、备份与 trace；生产环境仍必须配置随机 `GATEWAY_AUTH_TOKEN`，否则注册接口处于本机开发模式。
6. 声纹当前是轻量派生模板，需要真实用户样本的误拒率/误受率评估；未经评估不能宣称生产级身份认证。
7. 持续监听和主动提醒播报已经服从麦克风开关、Auto 切换、中断、冷却和免打扰；策略 UI 已写入 canonical Supervisor 配置，后续重点是生产环境下的提醒频率与打断成本校准。
8. 当前唤醒词由分段 STT 文本检测完成，功能边界明确但成本和延迟较高；生产部署应评估本地低功耗唤醒模型。
9. 身体槽位与 Gateway lane 是两种独立概念，不能用 lane 名称替代 slot 状态。
10. `AutonomousChainStore` 丢失后的恢复必须继续以 `memory_domain=evolution` 的 Mem 治理事件为准。
11. 任何新 Provider、技能或打包资源都必须经过退役集成扫描，不能留下隐藏回退。

这些问题的处理优先级应由架构核对清单中的产品答案决定；本文件不记录历史完成日志。
