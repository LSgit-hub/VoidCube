# 全链条报告：自主链路与用户链路边界审查

更新日期：2026-07-06

> 本报告只保留当前有效基线、当前问题清单和历史别名对照；不再把长迁移历史留在主文，避免退场术语反向污染后续判断。

## 1. 审查基准

本报告按最新《voidcube架构基线》审查全执行链路。当前最高优先级语义如下：

- **自主链路**：API-B 内生驱动自主感知、判断并生成治理投影/任务；Web 小屋只展示 API-B 的状态、反馈、任务治理和自主任务回报；API-A 自主执行面（当前仍由 `/auto` 临时门控的最小迷你 CLI / 子代理通道承载）拉取并执行 `self_learning` 与 `body_improvement`；成果写入 Mem；下一轮 API-B 再读取并继续判断。
- **用户链路**：用户通过主 CLI 调用 API-A 主 Agent，走 `user_chat` 泳道，服务当前用户请求。
- **硬边界**：自主链路与用户链路必须互不抢占、互不覆盖、互不被解释成同一个 CLI 模式。`/auto` 与 `/auto-q` 只是当前自主链路的临时启停开关，不是主 CLI 的用户交互模式。Web 小屋不是用户聊天入口，只是 API-B 主视角的观测面。

## 2. 当前结论

当前设计方向基本成立，且本轮已经完成以下关键收口：

1. **双链路主语已固定**：架构讨论优先使用“自主链路 / 用户链路”，不再把 `/auto` 误写成主 CLI 模式。
2. **执行者边界已固定**：任务生产者归 API-B / Supervisor；任务执行者归 API-A 自主执行面；成果回流归 Mem。
3. **Web 小屋职责已固定**：Web 小屋只观察 API-B 判断、治理反馈、Mem 回流，以及 API-A 回报给 API-B 的自主任务状态。
4. **主读模型已固定**：`autonomous_observation` 当前有效主树为 `board / chain / loop / runtime / counts`。
5. **链路分段已固定**：Web / dashboard / CLI 自主观察 helper 统一围绕 `autonomous_observation.chain.segments`，顺序为 `api_b_candidates -> api_b_backlog -> api_a_ready -> mem_recent`。
6. **创造类任务归属已固定**：未被 API-B 放行的 `self_learning / body_improvement` 仍属于 `api_b_backlog` 治理段，不会因为类型属于 API-A 能力域就自动出现在 `api_a_ready`。
7. **API-A 待拉取窗口语义已进一步收口**：`api_a_ready` 现在只承载真正“已放行、待 API-A 拉取”的链路项；已经进入 `running` 的 API-A 任务只留在 `loop.stages.api_a_execution` 与最近事件/轨迹里观察，不再混回待拉取窗口。

## 3. 当前链路对齐

### 3.1 自主链路

```text
API-B / Supervisor 内生驱动
  → 自主感知用户、系统、记忆、身体、治理状态
  → 形成 judgement / need / intent / governance output
  → 生成候选并管理治理在途项
  → API-A 自主执行面 pull 已放行任务
  → 执行 self_learning / body_improvement
  → 将结果、替身改进报告、任务 outcome 写入 Mem
  → 下一轮 API-B 读取 Mem 与任务历史继续判断
```

符合点：

- 任务生产归 API-B。
- 任务执行归 API-A 自主执行面。
- Mem 是结果回流位，不是执行槽。
- Web 小屋只展示这条闭环的 API-B 主视角观测。

### 3.2 用户链路

```text
用户
  → 主 CLI
  → API-A 主 Agent (`user_chat`)
  → 工具 / 临时上下文 / 必要记忆访问
  → 主 CLI 输出
```

符合点：

- 用户链路不依赖自主链路治理存储。
- 用户主 CLI 不承担自主任务执行槽。
- `/auto` 开关不得阻断用户输入或主 Agent 交互。

## 4. 当前协议与实现对齐点

- `read_model_version=8`。
- Web / 最小 dashboard / 主 CLI 自主观察 helper 统一消费 `autonomous_observation.chain.segments`。
- `loop.stages.api_a_execution` 直接承载 `status_label / chain_reason / activity_text / reason_style / focus_task`。
- `api_a_ready` 只统计 `approved / retry` 的放行待拉取项；`running` 任务属于执行中阶段，不再算作“待拉取窗口”。
- `board` 只保留 `headline / summary / primary_focus`；Web 小屋不再把 `board.current_cards` 作为主投影层。
- `board.protocol_notes`、segment `read_rule / next_step` 与 stage `read_rule / transition_hint` 已加入读模型，Web 小屋开始直接消费这些语义提示，而不是继续把旧技术字段硬拼成“任务台解释”。
- 主 CLI 自主执行面、监督事件镜像、最近执行摘要与 `/auto` 入口提示，已统一回到“链路项 / 链路裁决 / 执行焦点 / 自主链路”语义。
- Web 小屋已删除旧 `autonomous_observation.queue`、顶层 `api_b/api_a/mem/reread` 兼容镜像，以及 `presentation` 展示镜像层。
- Web 小屋这一轮继续去掉旧“队列台 / dispatch / LM 观察 / Perception → Intent”展示味：面板主语改回“API-B 判断输入 / 认知状态 / 自主链路分段观察”，用户链路信号只再作为“会话数 / 让路参考阈值”一类软感知说明出现。
- `ui_runtime` 内部围绕 API-A 段的旧 `dispatch` 命名也已继续收口到“execution lane / 待拉取窗口”语义，避免后续会话把自主链路观测层重新理解成旧分发队列。
- 内生驱动候选载荷入口与 backlog 计数主语已继续收口：候选载荷入口已统一到 `to_backlog_item()`，高频 backlog 压力/恢复/计数字段也已回到 `backlog` 语义，减少旧“总队列管理器”心智继续反向污染 Web 小屋与自主链路。
- 执行服务对外入口已进一步收口到自主链路主语：executor 侧正式执行入口改为 `/executor/autonomous-chain/execute`，返回状态改为 `autonomous_chain_execution_executed / autonomous_chain_execution_recorded`，不再继续把执行面叫成 `formal_self_evolution`。
- 最小迷你 CLI 中 API-A 子执行面的本地事件主语也已继续收口：`enqueue/prompt_queue` 一类命名已改成“执行提示注入 / execution prompt injected”，避免把 API-A pull/claim 执行面重新理解成旧本地消息队列。
- 监督者 scene 与循环摘要这一轮进一步统一为 `handoff / handed_off`，CLI、gateway、dashboard、Web 小屋不再同时混用“执行交接”文案与 `dispatch/dispatched` 旧键名。
- 主 CLI 这一轮继续收薄：`cli.py` 不再通过一组逐个转发的 runtime host wrapper 调自主执行逻辑，而是统一通过单个 autonomous runtime 实例桥接；`autonomous_runtime_host.py` 也已清掉那组重复转发函数。随后又去掉了一层状态格式化薄壳，测试直接回到 observation helper；`/auto` 激活时用到的 supervisor 快照获取与格式化也已下沉回 gate/status host。进一步地，`/auto-q / fast-exit / force-quit` 的退出路径也开始直接调用 host 上既有方法，不再由 `cli.py` 手工传一长串回调，本地 CLI 主类进一步回到“用户链路入口 + 薄桥接壳”。
- 主 CLI 已把自主观察 helper、panel 壳层、`/auto` gate、presence、events、runtime host、status host 下沉为独立模块；监督者快照摘要 wrapper 与 panel 侧状态读取 wrapper 已继续删除，autonomous panel 直接读取 status host 缓存，`/auto` gate 改成显式 callback 协作 runtime/status host，不再静默依赖已删除的 host 方法，`cli.py` 进一步收口为“用户链路入口 + 自主链路薄桥接壳”。

## 5. 当前架构判断

按最新语义，VoidCube 应被理解为“双链路共享底座”：

- 用户链路保证用户当前交互稳定、直接、优先。
- 自主链路负责 API-B 内生判断、API-A 自主学习/改进、Mem 闭环和 Web 可观测。
- 两者共享 API-A 能力域和 Mem，但必须通过 `user_chat / supervisor_task`、主 CLI / 最小迷你 CLI、用户输出 / API-B Web 观测这三层边界隔离。

因此，当前设计在目标方向上是成立的。当前主要风险已经不再是“缺少组件”，而是某些残留命名、残留文案或旧活动文档仍可能把自主链路误读成“主 CLI 的另一种运行模式”。
