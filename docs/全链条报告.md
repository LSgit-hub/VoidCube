# 全链条报告：自主链路与用户链路边界审查

更新日期：2026-07-07

> 本报告只保留当前有效基线、当前问题清单和历史别名对照；不再把长迁移历史留在主文，避免退场术语反向污染后续判断。

## 1. 审查基准

本报告按最新《voidcube架构基线》审查全执行链路。当前最高优先级语义如下：

- **自主链路**：API-B 内生驱动自主感知、判断并生成治理投影/任务；Web 小屋只展示 API-B 的状态、反馈、任务治理和自主任务回报；API-A 自主执行面（当前仍由 `/auto` 临时门控的最小迷你 CLI / 子代理通道承载）拉取并执行 `self_learning` 与 `body_improvement`；成果写入 Mem；下一轮 API-B 再读取并继续判断。
- **用户链路**：用户通过主 CLI 调用 API-A 主 Agent，走 `user_chat` 泳道，服务当前用户请求。
- **硬边界**：自主链路与用户链路必须互不抢占、互不覆盖、互不被解释成同一个 CLI 模式。`/auto` 与 `/auto-q` 只是当前自主链路的临时启停开关，不是主 CLI 的用户交互模式。Web 小屋不是用户聊天入口，只是 API-B 主视角的观测面。

## 2. 当前结论

当前设计方向基本成立，且本轮已经完成以下关键收口：

1. **双链路主语已固定**：架构讨论优先使用“自主链路 / 用户链路”，不再把 `/auto` 误写成主 CLI 模式。
2. **执行者边界已固定**：任务生产者归 API-B / Supervisor；任务执行者归 API-A 自主执行面；成果回流归 Mem。
3. **Web 小屋职责已固定**：Web 小屋只观察 API-B 判断、治理反馈、Mem 回流，以及 API-A 回报给 API-B 的自主任务状态。
4. **主读模型已固定**：`autonomous_observation` 当前有效主树为 `board / chain / loop / runtime / counts`。
5. **链路分段已固定**：Web / dashboard / CLI 自主观察 helper 统一围绕 `autonomous_observation.chain.segments`，顺序为 `api_b_candidates -> api_b_backlog -> api_a_ready -> mem_recent`。
6. **创造类任务归属已固定**：未被 API-B 放行的 `self_learning / body_improvement` 仍属于 `api_b_backlog` 治理段，不会因为类型属于 API-A 能力域就自动出现在 `api_a_ready`。
7. **API-A 待认领窗口语义已进一步收口**：`api_a_ready` 现在只承载真正“已放行、待 API-A 认领”的链路项；已经进入 `running` 的 API-A 任务只留在 API-A 执行阶段投影与最近事件/轨迹里观察，不再混回待认领窗口。
8. **Web 小屋边界又收紧了一圈**：架构基线与 UI 文案现在统一把 Web 小屋定义为“API-B 主视角只读观测房间”；`loop.stage_cards + loop.rail_entries` 为现役正式协议，`loop.stages` 进一步退到历史兼容位；API-A 相关展示也从“待认领 / 执行回报”收口到“认领 / 执行观测”，并明确“只看状态，不做人手调度”。
9. **formal handoff 与 CLI 主观察位又继续收薄**：`AutonomousChainExecutionRequest` 现在只继续支持 `activity_guard_evidence -> drive_input_evidence` 的 legacy 补齐，不再默认把 `drive_input_evidence` 反向回写成 `activity_guard_evidence`；同时 CLI 面板回归也补上了“`stage_cards` 与旧 `loop.stages` 同时存在时必须优先信任正式投影”的护栏。
10. **phase1 正式 auto 决策样例也开始脱离旧 request 体**：两条高可见的 memory maintenance auto decision 用例现在会先通过 probe 生成正式 `drive_input`，再以 `drive_input` 发起 `decide_autonomous_chain_task()`；`activity_guards: {"now": ...}` 不再占据这些正式 auto 决策样例的主请求体位置。
11. **显式 `activity_guards.now` 主请求体已进一步缩到退场路径**：当前 `phase1 / autonomous_chain_store` 里还保留这种旧请求体写法的样例，已经只剩 `skip` 的 body boundary 历史路径；活跃主回归里的正式 review/decide 样例已继续切到 `drive_input`。
12. **Web 小屋本地动作覆盖也已退场**：房间动作现在只再跟随 Supervisor 场景自动投影，不再保留浏览器侧手动 `rest/work/organize/write` 覆盖按钮；这让 Web 小屋进一步退回“只读观测房间”，减少被误读成人工控制台的概率。
13. **CLI 公共观测 helper 也不再默认吸收 `loop.stages`**：`autonomous_observation` 里的通用 `observation_loop_stage*` helper 现在只认正式 `stage_cards`；旧 `loop.stages` 只剩显式 compat helper 与专项回归入口，进一步压低默认读法把历史阶段镜像误当主协议的概率。
14. **自主判断返回壳也开始要求显式 compat**：`planning_runtime` 里的 `drive_input` response helper 现在默认只返回正式 `drive_input`；`activity_guards` 只在显式 legacy 请求或 probe/compat 路径下才继续对外保留，减少内部 legacy dict 被顺手带回正式结果面的概率。
15. **高频测试 helper 也继续退回正式主语**：`phase1` 里通过 probe 生成正式 `drive_input` 的 helper 已不再把 runtime probe 命名成 `legacy_runtime`，而 `autonomous_chain_store` 里少数必须同时携带 `drive_input + activity_guards` 的测试辅助构造器，也已显式改成 `explicit_compat` 口吻，进一步降低搜索结果把兼容样例误读成主协议入口的概率。

## 3. 当前链路对齐

### 3.1 自主链路

```text
API-B / Supervisor 内生驱动
  → 自主感知用户、系统、记忆、身体、治理状态
  → 形成 judgement / need / intent / governance output
  → 生成候选并管理治理在途项
  → API-A 自主执行面 pull 已放行任务
  → 执行 self_learning / body_improvement
  → 将结果、替身改进报告、任务 outcome 写入 Mem
  → 下一轮 API-B 读取 Mem 与任务历史继续判断
```

符合点：

- 任务生产归 API-B。
- 任务执行归 API-A 自主执行面。
- Mem 是结果回流位，不是执行槽。
- Web 小屋只展示这条闭环的 API-B 主视角观测。

### 3.2 用户链路

```text
用户
  → 主 CLI
  → API-A 主 Agent (`user_chat`)
  → 工具 / 临时上下文 / 必要记忆访问
  → 主 CLI 输出
```

符合点：

- 用户链路不依赖自主链路治理存储。
- 用户主 CLI 不承担自主任务执行槽。
- `/auto` 开关不得阻断用户输入或主 Agent 交互。

## 5. 当前架构判断

按最新语义，VoidCube 应被理解为“双链路共享底座”：

- 用户链路保证用户当前交互稳定、直接、优先。
- 自主链路负责 API-B 内生判断、API-A 自主学习/改进、Mem 闭环和 Web 可观测。
- 两者共享 API-A 能力域和 Mem，但必须通过 `user_chat / supervisor_task`、主 CLI / 最小迷你 CLI、用户输出 / API-B Web 观测这三层边界隔离。

因此，当前设计在目标方向上是成立的。当前主要风险已经不再是“缺少组件”，而是某些残留命名、残留文案或旧活动文档仍可能把自主链路误读成“主 CLI 的另一种运行模式”。
