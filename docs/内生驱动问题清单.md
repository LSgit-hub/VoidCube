# 内生驱动问题清单

## 1. 这份清单解决什么

这份文档不是另一份设计书，也不是另一份质量基线。

它只回答四件事：

- 当前最新版内生驱动还剩哪些真实问题
- 哪些问题已经解决，哪些只是阶段性缓解
- 下一轮实现该优先处理什么，避免重新跑偏
- 如何判断后续修改是在收敛还是在回退

与其他文档的分工保持不变：

- [内生驱动核心设计](./内生驱动核心设计.md)：定义“内生驱动是什么”
- [内生驱动质量基线](./内生驱动质量基线.md)：定义“当前阶段优先守住哪些边界”
- 本文：根据最新版代码与回归结果，更新“剩余问题是什么”

## 2. 当前总判断

当前实现已经明显走出了“高级任务生成器”的旧主线，进入了“认知判断 + 治理输出”主线，但还没有完全收敛。

和前一阶段相比，几个关键点已经发生变化：

- runtime 状态里已经有更前置的主判断层入口 `judgement_core`
- `need -> intent -> governance channel` 已经有了更明确的回归保护
- 弱场景下“正确的不行动”已经有系统级测试保护
- 多轮 history 下 `task_type` 已经不容易再直接反向接管 meta-cognition posture

所以最新版的核心判断不再是“主线还没切过去”，而是：

> 主线已经切过去了，但兼容层仍偏厚、部分旧命名仍在、重复摘要还没完全收完。

基于最近一轮代码与回归补强，这个判断还需要再向前推进半步：

- 现在的主要风险已经不再是“会不会随时退回旧主线”
- 更真实的风险已经收缩成“长链路下是否还会慢性漂移，或被残留兼容层重新解释”

也就是说，当前内生驱动的状态已经更接近：

> 主线已稳定切换完成，当前重点从“防止方向性跑偏”转向“证明多轮连续运行下仍不慢性失稳”。

## 3. 已确认完成的收敛

### 3.1 文档主定义已统一

目前文档层已经不再是两套分叉叙事：

- 主定义已经统一到“认知核心 + 治理输出中枢”
- 质量基线已经明确是设计约束，不再是第二份设计
- LM 提示词设计已并回主设计，不再单独构成第二主线

这部分目前不再是主要问题。

### 3.2 “正确的不行动”已补上核心保护

当前已经明确具备以下保护：

- 弱证据允许空 `proposals`
- LM 空 `proposals` 时不会偷偷补出 LM 候选
- 同类弱场景下不会回退成 `body_improvement` / 泛化 learning fallback
- 弱 improvement 不会压过更保守的 review

这意味着“为了显得主动而硬凑任务”的风险已经明显下降。

### 3.3 通道选择稳定性已有实质进展

当前已经补上并验证了关键链路：

- `repair_truthfulness -> review_truthfulness_signals -> truthfulness channel`
- 即使 `observe_before_acting` 同时存在，truthfulness 通道也不会被总观察姿态吞掉

这说明通道选择已经不只是“看起来有多通道”，而是开始有真实链路稳定性。

### 3.4 兼容字段已不再轻易反客为主

当前已经补上并验证了这类场景：

- 历史 judgement 明确偏向 `review / grounding`
- `why_not_improvement_now` 明确存在
- 兼容字段里的 `top_priority_task_type` 恰好是 `learning`

在这种情况下，`recommended_task_posture` 不再被直接拉回 `learning`。

这意味着“多轮后被 task prior 重新带偏”的最危险那条回退路径已经被切断。

### 3.5 `judgement_core` 主 intent 已不再轻易跳轴

当前已经补上并验证了这类场景：

- 主 `need` 明确是 `repair_truthfulness`
- `observe_before_acting` 因为局部优先级修正，在 `intent` 排序里暂时更高
- runtime 仍需要给出主判断链上的主 `intent`

在这种情况下，`judgement_core.primary_intent` 不再直接机械取 `intents[0]`，而会优先对齐主 `need` 的同源 `intent`。

这意味着 runtime 主判断层已经不那么容易出现“主 need 在一条轴上，主 intent 跳到另一条轴上”的错位问题。

### 3.6 `primary_need` 已不再直接受 append 顺序支配

当前已经补上并验证了这类场景：

- `stabilize_memory_continuity` 因为分支顺序更早被 append
- `repair_truthfulness` 在当前窗口里实际更强
- runtime 仍需要给出主判断链上的主 `need`

在这种情况下，`needs` 不再只是按分支追加顺序暴露给后续主判断层，而会先按 `severity / urgency / confidence` 的综合强度排序。

这意味着 `judgement_core.primary_need` 已经不再那么容易变成“谁先写在前面谁就是主 need”的偶然结果。

### 3.7 纯评估路径已不再把 history 自反馈放大

当前已经补上并验证了这类场景：

- 相同窗口连续多次执行 `evaluate_endogenous_drive(record_activity=False)`
- 没有新的外部 outcome 进入
- `historical_underdelivery` 已经成立，系统本来就偏 observation

在这种情况下：

- 不会再因为一次评估里的中间候选重跑，导致 `focus / agenda / observation` 记忆被同轮重复写入
- `observation_target_stats` 的未解决压力不再因为刚出现一次 recommendation 就被立即当成历史阻塞持续放大
- `observation_bias` 不会再在 1 到 2 轮纯评估里被自反馈直接推到 1.0

这意味着当前已经补上了一个真实的 history 放大 bug：系统不再那么容易因为“只是重复看了一眼自己”就把下一轮判断推得越来越极端。

### 3.8 `planned` 已不再提前污染拖延统计

当前已经补上并验证了这类场景：

- 内生驱动刚把候选投影进任务列表
- outcome 只有 `planned`
- 还没有真实 decision / execution 结果回来

在这种情况下：

- `planned` 仍会保留在 `outcomes` 里，供后续追踪
- 但不会再被记进 `focus_stats.dragging`
- 也不会再把某个 `preferred_focus` 在“尚未发生结果前”提前判成低效或拖延

这意味着当前又切掉了一条会扭曲 history 反馈的伪结果路径：计划本身不再冒充拖延结果。

### 3.9 `meta_cognition_profile` 已不再被默认低压信号误判为可用

当前已经补上并验证了这类场景：

- 没有真实 `current_judgement / dominant_constraint / self_iteration` 线索
- 没有真实 post-task effect / drift / grounding 异常
- 只有默认推导出来的 `grounding_pressure=low`

在这种情况下：

- `meta_cognition_profile.available` 不会再被机械标成 `true`
- runtime 也不会再把“默认低压 + 默认 review 姿态”误展示成已有一份真实 meta-cognition judgement

这意味着又补上了一条轻微但真实的伪状态问题：系统不会再因为默认值存在，就假装自己已经形成了认知判断摘要。

### 3.10 runtime fallback 已不再漏掉 `recent_reference_alignment`

当前已经补上并验证了这类场景：

- 没有最新一轮 LM reasoning state
- 但 history 里已经存在真实 `reference_alignment`
- runtime 仍需要构造 `proposal_cognition` 与 fallback `meta_cognition_profile`

在这种情况下：

- `proposal_cognition.recent_reference_alignment` 不会再因为 LM state 为空而退回全空
- fallback `meta_cognition_profile` 也不会再忽略真实 grounding 漂移，只靠其他记忆层机械生成判断

这意味着又补上了一条真实的 fallback 断层：runtime 的历史回补现在不再只补 assessment / trend / effect，却把 reference alignment 单独漏掉。

### 3.11 `historical_underdelivery` 已不再被单次恢复结果立即翻轴

当前已经补上并验证了这类场景：

- history 里已经连续存在多条 `failed / deferred / awaiting_review` 的 self-learning 结果
- 系统当前主轴已经进入 `historical_underdelivery -> observe_before_acting`
- 之后只额外进入一条 `completed` self-learning 结果

在这种情况下：

- `dominant_constraint` 不会再因为这一条恢复结果立刻从 `historical_underdelivery` 掉回 `none`
- `judgement_core.primary_need` 也不会再直接从 `observe_before_acting` 跳回 `expand_learning_frontier`

这意味着当前又补上了一条真实的主轴脆弱点：系统不会再因为“刚恢复一次”就过早认定 underdelivery 已经解除。

### 3.12 `historical_underdelivery` 已不再被异家族恢复结果冲淡

当前已经补上并验证了这类场景：

- history 里已经连续存在多条 `failed / deferred / awaiting_review` 的 `self_learning` 结果
- 系统当前主轴已经进入 `historical_underdelivery -> observe_before_acting`
- 后续额外进入的是 `memory_maintenance completed` 一类的异家族恢复结果

在这种情况下：

- `historical_underdelivery` 不会再因为其他家族的完成结果被提前冲淡
- `dominant_constraint` 不会再把 `memory_maintenance` 的恢复错误当成 `self_learning` 通道已经恢复
- 只有 `self_learning` 自己的连续恢复结果，才会真正推动这条约束退出

这意味着当前又切掉了一条真实的跨通道污染 bug：learning 通道的历史 underdelivery 不会再被别的通道“代偿式冲账”。

### 3.13 prompt 前台已不再把兼容投影当成主判断句暴露

当前已经补上并验证了这类场景：

- LM prompt 仍然需要保留 `task_type_priors / compatible_projection_bias` 这类兼容参考
- 但当前真正的主判断已经由 `decision_core / governance_posture / grounding` 主导
- 后续 prompt 简报如果仍把“最强任务投影偏向”写成主句，很容易把旧主线重新抬回前台

在这种情况下：

- cognitive briefing 不会再把兼容投影写成主判断句
- 兼容投影现在只作为“兼容提示”保留，并明确标成“仅作兼容参考，不得覆盖当前判断与治理姿态”
- 默认 prompt attention 顺序里，`task_type_priors` 也已经继续后移，不再排在高优先层前列

这意味着当前又收掉了一块真实的前台误导残留：兼容投影仍保留给程序使用，但不再在 prompt 正文里抢主判断层的可见性。

### 3.14 `historical_underdelivery` 的预算节流口径已与主约束口径一致

当前已经补上并验证了这类场景：

- `reflection` 已经根据 `self_learning` 自身 history 判定 `historical_underdelivery`
- 但 `adaptive_policy` 仍可能按全家族混算 `historical_drag_ratio`
- 于是只要 `memory_maintenance` 一类的其他家族连续成功，`candidate_budget` 就可能被提前放松

在这种情况下：

- `adaptive_policy` 不会再因为其他家族成功，就在 `historical_underdelivery` 仍成立时悄悄把预算重新放宽
- `candidate_budget` 的保守收紧口径，已经与 `reflection` 的 self-learning underdelivery 作用域对齐
- runtime 不会再出现“主约束还说 underdelivery 仍在，但预算已经按全局恢复放松”的内部不一致

这意味着当前又切掉了一条真实的策略层断裂：underdelivery 的主约束与输出节流不再各用一套 history 口径。

### 3.15 `observation` 模式下已不再被兜底逻辑复活 learning fallback 候选

当前已经补上并验证了这类场景：

- `historical_underdelivery` 已经成立
- `preferred_focus=observation`
- `candidate_budget` 与 `exploratory_learning_quota` 已经把 learning / body 候选压掉
- 当前轮次里又恰好没有 truthfulness / queue / memory 这类允许保留的 observation-oriented 候选

在这种情况下：

- 自适应预算过滤后不会再因为“至少保留一个候选”的兜底逻辑，把刚被压掉的 `generic_learning_fallback` 或其他 learning 候选重新捞回来
- runtime 不会再出现“主判断要求先观察，但 candidate 列表里仍塞回 learning fallback”的执行层自相矛盾
- observation 模式下如果当前没有允许的稳定性候选，结果现在会真实返回空候选，而不是假装还有一个 learning 投影

这意味着当前又切掉了一条真实的执行层裂缝：输出候选列表现在和 observation 主轴保持一致，不会再被兜底分支反向复活旧候选。

### 3.16 `queue_hygiene` 单独路径已不再因为 `shell_slot_meta` 作用域问题崩溃

当前已经补上并验证了这类场景：

- `self_learning` 路径被关闭
- 只保留 `general_self_evolution / queue_hygiene_review` 这条治理候选路径
- 当前轮次需要直接进入 queue hygiene 候选生成

在这种情况下：

- `_candidate_stream()` 不会再因为 `shell_slot_meta` 只在 learning 分支里定义，而在后续 queue/body 分支引用时触发 `UnboundLocalError`
- queue hygiene-only 路径现在可以独立完成候选生成
- `queue_hygiene_review` 候选可以在不依赖 self-learning 分支初始化的前提下稳定进入结果

这意味着当前又切掉了一条真实的代码缺陷：允许候选本身不是被策略压掉，而是此前会被局部变量作用域错误直接卡死。

### 3.17 多轴叠加时 `truthfulness` 主轴已不再被预算裁剪错位成 `memory_maintenance`

当前已经补上并验证了这类场景：

- `repair_truthfulness`
- `historical_underdelivery`
- `clear_governance_backlog`

这几条轴同时存在，并且当前轮次 `candidate_budget=1`

在这种情况下：

- `judgement_core.primary_need` 与 `primary_intent` 如果已经明确落在 `repair_truthfulness / review_truthfulness_signals`
- 候选保留阶段不会再只按纯 `utility` 把 `memory_maintenance` 顶上来
- `truthfulness_review` 现在会优先作为与当前主焦点对齐的候选留下

这意味着当前又切掉了一条真实的主轴错位问题：主判断链已经明确要求修 truthfulness 时，输出候选不会再被预算裁剪回到别的治理轴上。

### 3.18 `queue_hygiene` 候选已不再在 `observation` 主轴下被 `memory_maintenance` 顶掉

当前已经补上并验证了这类场景：

- 当前主轴已经进入 `observe_before_acting`
- `governance_review_suggestion` 已明确指向 `review_queue_hygiene`
- `candidate_budget=1`
- 候选池里同时存在 `queue_hygiene_review` 和 `memory_maintenance`

在这种情况下：

- 候选保留阶段不会再因为纯 `utility` 排序，继续把 `memory_maintenance` 放在 `queue_hygiene_review` 前面
- observation 模式下如果 queue review 信号已经成立，`queue_hygiene_review` 现在会优先作为对齐当前治理焦点的候选留下
- observation 模式下当 `truthfulness_review` 与 `queue_hygiene_review` 同时存在时，候选保留现在会优先按当轮 `drive_judgement` 里的主 intent / 主 need 强度裁决，而不是再被纯 `utility` 反转
- runtime 不会再出现“信号层明确要求 review queue hygiene，但最终候选仍回到 memory 轴”的错位

这意味着当前又切掉了一条对称的预算裁剪错位：`queue_hygiene` 现在和 `truthfulness` 一样，已经在主轴对齐上获得了候选保留保护。

### 3.19 `historical_underdelivery` 下的 `preferred_focus` 已与 observation 主轴重新对齐

当前已经补上并验证了这类场景：

- `self_learning` 通道先连续 underdeliver
- 中间出现同家族恢复结果
- 随后又继续进入新的 self-learning 拖延 / retry
- 同时 history 里还混入了 `memory_maintenance completed` 一类异家族成功项

在这种情况下：

- 只要 `historical_underdelivery` 仍成立，且高 observation bias 已重新形成
- `adaptive_policy.preferred_focus` 就不会再被 `memory_continuity` 一类偏置重新抢走
- runtime 现在会把 `dominant_constraint / preferred_focus / primary_need / candidate_budget / exploratory_learning_quota` 继续收回同一条 observation-first 主链

这意味着当前又切掉了一条真实的半分叉残留：之前虽然 `primary_need` 已经被补回 `observe_before_acting`，但 `preferred_focus` 仍可能停在 memory continuity；现在策略层和判断层的主轴重新对齐了。

### 3.20 `self_learning` 恢复后最近再次拖延，已能重新进入 `historical_underdelivery`

当前已经补上并验证了这类场景：

- `self_learning` 先出现连续 underdeliver
- 中段出现连续 recovery，系统一度具备退出 underdelivery 的条件
- 但最近几条 self-learning 结果里，又重新出现连续 `deferred / retry / failed`
- history 中还可能夹杂 `memory_maintenance completed` 一类异家族成功项

在这种情况下：

- `reflection` 不会再只看整段 self-learning 总账，把最近这轮 relapse 冲淡掉
- 只要 recent relapse 已经形成，系统就会重新回到 `historical_underdelivery -> observe_before_acting`
- `adaptive_policy` 也会和这条主判断共用同一份历史压力口径，而不是各自读出不同结论

这意味着当前又切掉了一条真实的退出边界迟钝问题：以前系统会在“恢复过一次”之后，对最近重新变差的 self-learning 链反应过慢；现在 recent relapse 已经能把主轴重新拉回 observation-first。

### 3.21 带真实时间戳的同一组 outcome，已不再因为列表顺序不同而改写主判断

当前已经补上并验证了这类场景：

- history 里的 outcome 事实集合完全相同
- `recorded_at` 已经能表达真实先后顺序
- 但传入列表本身可能是 newest-first、oldest-first，或被中途打乱

在这种情况下：

- `reflection` 与 `adaptive_policy` 在读取历史前，会先按真实时间戳归一化 outcome 顺序
- `historical_underdelivery / preferred_focus / primary_need` 不会再因为同一批事实只是列表摆放不同而跳变
- recent relapse 的识别也会优先遵循真实发生顺序，而不是直接吃当前数组排布

这意味着当前又切掉了一条真实的顺序敏感残留：以前即使事实相同，只要 outcome 数组排布不同，underdelivery 主轴就可能一会儿成立、一会儿不成立；现在带时间戳的历史已经收回统一口径。

### 3.22 无时间戳旧历史在顺序不可靠时，已退回更保守的一致口径

当前已经补上并验证了这类场景：

- history 来自旧数据，缺少 `recorded_at / completed_at / updated_at / created_at`
- `self_learning` 同时包含早期 underdeliver、中段 recovery、以及最近再次恶化的混合状态
- 同一组事实只因数组顺序不同，就可能把主轴带成不同结论

在这种情况下：

- 系统不会再假设当前数组顺序一定可信
- 对这类无时间戳、且恢复/拖延混杂的旧历史，主判断会退回更保守的一致口径
- runtime 会优先维持 `historical_underdelivery -> observe_before_acting`，而不是在顺序不可靠时贸然切回 learning-expansion

这意味着当前又切掉了一条旧历史兼容残留：以前无时间戳历史只要顺序稍乱，就可能在 observation-first 和 expansion-first 之间抖动；现在旧数据至少会保守地维持一致。

### 3.23 recent relapse 重新触发 underdelivery 时，预算节流已重新与主约束对齐

当前已经补上并验证了这类场景：

- `historical_underdelivery` 不是靠整段拖延比直接成立
- 而是靠 recent relapse 在更长 mixed history 里重新触发
- 这时 `dominant_constraint / primary_need / preferred_focus` 已经回到 observation-first
- 但旧逻辑里 `candidate_budget` 仍可能停在 `4`

在这种情况下：

- 只要 underdelivery 是被 recent relapse 重新点亮的
- `candidate_budget` 也会同步重新收紧，不再继续沿用过宽的旧预算
- runtime 现在不会再出现“主判断已经要求先观察，但预算节流还像扩张态一样放着”的策略层脱轴

这意味着当前又切掉了一条真实的长链脱口径残留：以前 longer mixed history 里，recent relapse 虽能把主 need 拉回 observation-first，但 budget 仍可能滞后；现在主约束、主 need 和预算节流重新同口径了。

### 3.24 runtime 主视图已不再通过 `lm_trace` 外露 `top_priority_task_type`

当前已经继续收掉了一条容易把后续理解拉回旧范式的运行态残留：

- 内部 LM task generation 仍然可以保留 `task_type_priors.top_priority_task_type` 作为兼容投影输入
- 但 runtime 主视图里的 `proposal_cognition.lm_trace` 不再继续把它作为前台字段外露
- `lm_trace` 现在只保留 `available / status / model_role / charter_core_mission / proposal_count`

在这种情况下：

- runtime 主视图不会再通过 `proposal_cognition.lm_trace.top_priority_task_type` 暗示“当前最重要的是 task type 投影”
- 后续新会话即使只看主状态结构，也更难把兼容投影误当成主判断输出
- 内部 prompt / evidence / scoring 仍可继续使用该兼容信息，不会因为这次瘦身破坏真实生成链

这意味着当前又切掉了一条真实的前台兼容误导：以前虽然 `task_type_priors` 已退出 `proposal_cognition` 第一层，但 `lm_trace` 里仍残留一个 `top_priority_task_type` 小窗口；现在连这个窗口也收掉了。

### 3.25 `observe_before_acting` 已成立时，`memory_maintenance` 不再作为 observation 模式的兜底候选复活

当前已经补上并验证了这类场景：

- `historical_underdelivery` 已成立
- `judgement_core.primary_need / primary_intent` 已明确落在 `observe_before_acting`
- `adaptive_policy.preferred_focus=observation`
- `candidate_budget=1`
- 同时当前轮次只有 `memory_maintenance` 还具备 planning 资格

在这种情况下：

- observation 模式下的候选保留不再把 `memory_maintenance` 当作允许兜底项
- 如果没有 `truthfulness_review / queue_hygiene_review` 这类与 observation 主轴对齐的候选，runtime 现在会直接返回空候选
- 系统不会再出现“主判断要求先观察，但输出仍悄悄退回 continuity 任务”的半回退

这意味着当前又切掉了一条真实的旧主线残留：以前 observation-first 虽然已经成为主判断，但候选预算裁剪里仍给 `memory_maintenance` 留了一个后门；现在这个后门已经收掉了。

### 3.26 `truthfulness` 主轴与 observation 门控并存时，`drive_posture_signal` 已补回观察意图关联

当前已经补上并验证了这类场景：

- `repair_truthfulness` 是当前主 `need`
- `primary_intent` 已正确落在 `review_truthfulness_signals`
- 同时 `historical_underdelivery` 仍成立，`observe_before_acting` 也还在 active needs 里
- runtime 会继续发出 `drive_posture_signal`

在这种情况下：

- `drive_posture_signal.payload.preferred_focus` 仍然可以保持 `truthfulness`
- 但它的 `source_needs / related_intent` 不会再变成半截状态
- 只要 observation 门控真实存在，`drive_posture_signal.related_intent` 现在就会明确连回 `observe_before_acting`

这意味着当前又切掉了一条真实的前台信号脱口径：以前主判断、主意图和最终候选都已经对齐，但 posture signal 仍可能把 observation need 挂上去，却把对应 intent 留空；现在 signal 层也补回统一口径了。

### 3.27 observation 模式下 `truthfulness_review / queue_hygiene_review` 同分时，候选保留已不再受输入顺序影响

当前已经补上并验证了这类场景：

- 当前轮次已经进入 observation 模式
- `truthfulness_review` 与 `queue_hygiene_review` 都属于允许候选
- 两者的 `drive_judgement` 强度与 `utility` 恰好打平
- 只是候选输入数组顺序不同

在这种情况下：

- 候选保留不再直接吃输入顺序
- observation 模式下会使用稳定的最终 tie-break，保证同一组事实不会一会儿留 `truthfulness_review`、一会儿留 `queue_hygiene_review`
- 同时如果其中一边后来真的略强，系统仍会按真实强度单调切换，不会被 tie-break 反压

这意味着当前又切掉了一条真实的排序稳定性残留：以前 observation 模式下两个允许候选一旦完全同分，谁先进列表谁就赢；现在这个边界已经收回稳定口径了。

### 3.28 弱 truthfulness 信号下，`truthfulness_review` 已不再早于观察阈值提前候选化

当前已经补上并验证了这类场景：

- `historical_underdelivery` 已经成立，主判断仍停在 `observe_before_acting`
- `correction_signals` 只有 `1`
- `repair_truthfulness` 只是较弱次级 need
- signal 层也还没有进入 truthfulness-focused observation

在这种情况下：

- runtime 不会再提前把 `truthfulness_review` 候选直接塞进最终输出
- `truthfulness_review` 现在会和 truthfulness observation signal 共用更一致的进入门槛
- 只有当 `correction_signals` 真正达到 review threshold 后，它才会进入候选层

这意味着当前又切掉了一条真实的阈值错位：以前主 need、主 intent 和 signal 还在 observation-first，但候选层已经抢先物化 truthfulness review；现在 need / signal / candidate 三层门槛重新对齐了。

### 3.29 弱 queue debt 下，`queue_hygiene_review` 已不再早于 review signal 提前候选化

当前已经补上并验证了这类场景：

- `historical_underdelivery` 已成立，主判断仍停在 `observe_before_acting`
- `clear_governance_backlog` 只是较弱次级 need
- `pending_review_count=0`、`stale_queue_count=0`
- signal 层也还没有进入 `governance_review_suggestion`

在这种情况下：

- runtime 不会再提前把 `queue_hygiene_review` 候选直接塞进最终输出
- `queue_hygiene_review` 现在会和 queue review signal 共用更一致的进入门槛
- 只有当真实 queue debt 已经存在时，它才会进入候选层

这意味着当前又切掉了一条和 truthfulness 对称的阈值错位：以前 need / signal 还在 observation-first，但 queue review 候选已经抢先物化；现在 queue 轴的 need / signal / candidate 三层门槛也重新对齐了。

### 3.30 cleared window 下的复合 observation carryover 已不再把主轴卡死

当前已经补上并验证了这类场景：

- `historical_underdelivery` 已经解除，`dominant_constraint=none`
- `strategy_memory` 对 `observation` 仍保留较强历史成效
- persisted `self_regulation` 仍残留 observation / throttle / learning suppression carryover
- posture 又手动停在 `observe_first`
- LM reasoning state 仍处于 `correcting`，但并不是强烈失稳

在这种情况下：

- 当前轮新的 `cognitive_self_regulation` 不会再继续把 observation / throttle / suppression 再叠高一层
- persisted carryover 仍会保留为衰减中的背景约束，但不会再把 cleared window 重新强行拉回 observation-first
- `preferred_focus`、`primary_need` 和最终学习扩张窗口现在可以重新回到 cleared state 应有的口径

这意味着当前又切掉了一条真正的系统级复合漂移风险：姿态、策略记忆和持续自调节不再会在约束已清空后，把主轴重新卡死在旧观察链上。

### 3.31 多轮 continuity / memory 写回后，truthfulness 仍可接管主轴

当前已经补上并验证了这类场景：

- 连续多轮 `evaluate_endogenous_drive -> plan -> outcome writeback`
- history 里 `focus_stats / contextual_focus_stats / outcomes` 持续累积
- 中间轮次可能落在 `memory_continuity`、`observation`，甚至提前进入 `truthfulness`
- 最终再切到 `strained` context，且 `correction_signals` 达到真实 review threshold

在这种情况下：

- 系统不会再因为前面几轮的 continuity 写回，就把 `truthfulness` 永久卡在次级位
- 当 review threshold 真正成立时，`preferred_focus` 仍会稳定切到 `truthfulness`
- `judgement_core.primary_need` 也仍会落在 `repair_truthfulness`

这意味着当前又补上了一条长期主轴护栏：连续多轮 history 写回不会轻易把 truthfulness 接管能力锁死。

### 3.32 多轮 mixed writeback + context switch 下，主轴没有出现慢性锁死

当前已经补上并验证了这类场景：

- 连续多轮混合 `completed / deferred / failed` 写回
- context 在 `stable / degrading / strained` 之间切换
- `focus_stats / observation_target_stats / meta_governance_stats` 三层同时跨轮累积

在这种情况下：

- `observed_contexts / observed_meta_modes / observed_focuses` 都会真实扩展，而不是被单一模式长期吞掉
- `meta_governance_stats` 会跨轮保留记忆，但不会把最终模式永久锁死在旧的 `expand` 或 `conserve`
- 最终当 `strained + truthfulness threshold` 再次成立时，系统仍会落回 `truthfulness / repair_truthfulness`

这意味着当前已经拿到第一批真正的长序列证据：策略记忆、观察目标记忆和 meta-governance 记忆会累积，但目前没有看到把主轴慢性锁死到旧 focus 的现象。

## 4. 当前仍然存在的真实问题

### 问题 1：命名与外层接口仍带旧“任务评估器”惯性

当前主实现已经不是“先定任务，再反推判断”，但这些名字仍然会把读者带回旧理解：

- `evaluate_endogenous_drive()`
- `/runtime/endogenous-drive/evaluate`
- `EndogenousTaskCandidate`
- `proposal_cognition`

这已经不再是主逻辑分叉，而是接口层认知风险。它最危险的地方不是当前行为错误，而是后续新会话容易顺着名字继续往“候选任务中心制”上加东西。

### 问题 2：内部仍有兼容残留，尤其是 `task_type` 语义惯性

当前 runtime 前台已经不再把 `top_priority_task_type` 当主输出，prompt 前台也不再把兼容投影写成主判断句，这是很大的收敛。

但内部仍然留着一批兼容残留：

- `compatible_projection_bias`
- `task_type_priors`
- 以 candidate 为中心的部分 scoring / fallback / merge 理由

所以现在的问题不是“外面还像两套系统”，而是“里面仍有一部分旧骨架没有完全退场”。

### 问题 3：`proposal_cognition` 已降级，但仍然偏厚

当前真正承载主判断的前台结构已经比较明确：

- `judgement_core`
- `attention_agenda`
- `uncertainty_ledger`
- `observation_program`
- `meta_governance`

`proposal_cognition` 现在更像辅助观察层，已经明显收薄：

- `lm_reasoning_state` 收成 `lm_trace`
- `cognitive_assessment_memory` 收成 `assessment_trace`
- `cognitive_feedback_memory / cognitive_strategy_delta / cognitive_evolution_draft` 收成 `cognitive_evolution_trace`
- 更细的 self-iteration 材料收成 `self_iteration_focus`

剩下的真实问题不是“顶层又分出第二套主系统”，而是它仍然偏厚，仍然容易被误读成与 `cognition_state` 并列的一层主结构。

### 问题 4：长链路稳定性验证已经初步建立，但还没覆盖更长和更脏的真实序列

现在 need / intent / signal / candidate 这条链在 memory、truthfulness、queue、observation 几条主轴上已经比之前整齐很多，近期也补齐了几类关键边界：

- observation-first 不再回退成 `memory_maintenance`
- `drive_posture_signal` 不再把 observation gating 和 truthfulness 主轴写成半分叉
- truthfulness 与 queue review 的弱信号不再提前物化 candidate
- observation 模式下 truthfulness / queue review 的平分与轻微超越已经有确定性与单调性回归
- continuity / memory 多轮写回后，truthfulness 仍可接管
- mixed writeback + context switch 下，主轴目前没有出现慢性锁死

这说明“长链路稳定性”已经不再是完全空白，而是进入了“第一批系统级回放已经补上，但覆盖面还不够大”的阶段。

真正还薄弱的是更长、更脏、更贴近真实运行的稳定性：

- 更长周期下 `primary_need` 是否仍稳定
- 更复杂 outcome 污染下，主轴是否会不合理跳变
- `preferred_focus`、budget、review gate、learning quota 在更脏 history 组合下是否始终同口径
- persistence memory 是否会在更长时间跨度里把 `meta_governance` 稳态慢慢推偏

也就是说，当前最缺的已经不是“别走错方向”的护栏，而是“更长周期、更多噪声下仍保持同一判断口径”的持续稳定性证明。

### 问题 5：任务候选仍然是最大实现体量

虽然前台定义已经前移到认知判断和治理输出，但从代码体量和实现重心上看：

- `task_candidates` 相关逻辑仍然最多
- LM materialization 仍主要围绕 candidate
- 很多 merge / ranking / trimming 仍主要服务 candidate 保留

这不代表现在的实现是错的，但意味着如果后续工作继续只沿着 candidate 修补，系统很容易再次被拖回旧范式。

## 5. 最新优先级

### P0：继续补更长周期的稳定性回归

当前最值得优先做的，不是再改定义，而是把这条稳定性证明继续往前推：

- `judgement_core.primary_need`
- `primary_intent / preferred_focus`
- observation gate
- review gate
- candidate budget / learning quota

现在已经补上了多轮 continuity 写回、mixed writeback 和 context switch 的第一批回放。

下一步要优先覆盖：

- 更长周期的 `completed / deferred / failed / retry / paused` 混合序列
- 结构更脏的 outcome 组合
- 多次 posture 变化与 self-regulation 衰减交织
- persistence memory 在更长时间跨度里的累积副作用

### P1：继续削薄兼容层

这一层现在已经不是“救火”，而是“防止旧范式回潮”：

- 继续压 `proposal_cognition`
- 继续减少 `compatible_projection_bias / task_type_priors` 的存在感
- 继续避免重复摘要重新长回来

### P2：最后再做接口收口

等稳定性和内部厚度都更扎实后，再处理这些名字会更顺：

- `evaluate_endogenous_drive()`
- `proposal_cognition`
- `EndogenousTaskCandidate`

这一步应该是收口，不应该是现在的主战场。

## 6. 当前不建议优先做的事

现阶段仍然不建议优先推动：

- 再增加新的认知术语层
- 再扩新的治理输出面
- 为了展示更全而继续往 runtime state 塞更多说明字段
- 在未验证稳定性前大改命名或大改对象层级

## 7. 建议的下一轮顺序

建议下一轮按这个顺序推进：

1. 先补 `judgement_core.primary_need` 和 `preferred_focus` 的长链路稳定性回归，重点看多轮 outcome 连续写回、恢复后再受阻、混合家族交错恢复时会不会跳轴
2. 然后继续压 `proposal_cognition` 和内部 `task_type` 兼容残留，把还能下沉的观察痕迹继续下沉，避免 runtime 前台重新长厚
3. 最后再决定是否做接口重命名与对象收口，把外层命名和当前真实语义对齐

## 8. 一句话结论

当前内生驱动已经不再是“两套主系统分叉”的状态，而是：

> runtime 前台主线已经稳定收敛到“认知判断 + 治理输出选择”；当前剩下的主要问题，不再是方向性跑偏，而是内部兼容残留仍偏厚，以及更长周期稳定性证明还不够充分。

下一阶段最重要的不是继续扩能力，而是继续削弱兼容层存在感，并把 `judgement_core` 这条主判断链在更长、更脏真实序列下的稳定性验证补完整。
