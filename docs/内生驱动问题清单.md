# 内生驱动问题清单

## 1. 这份清单现在只做什么

这份文档不再充当“修复历史流水账”。

从现在开始，它只保留三类内容：

- 当前内生驱动已经取得了什么成果
- 当前还剩哪些真实未解的问题
- 下一轮最值得做什么

已经处理完成的问题，不再继续在这里无限累积；需要追溯历史时，直接看 git 历史、测试和专题报告。

## 2. 当前成果回顾

### 2.1 主定义已经收口

内生驱动现在已经不再是两套分叉叙事：

- 主定义统一为“监督者的认知核心 + 治理输出中枢”
- 质量约束口径已并回问题清单与专题报告，不再和设计文档争主线
- LM 提示词设计已经并回主设计，不再单独形成第二套核心定义
- `voidcube架构基线` 对内生驱动的表述也已经基本对齐

这意味着文档层的主分叉已经收住。

### 2.2 运行时主线已经切换完成

当前 runtime 前台的主结构已经明确前移到：

- `judgement_core`
- `attention_agenda`
- `uncertainty_ledger`
- `observation_program`
- `meta_governance`

`task_candidates`、`proposal_cognition` 这类内容仍然存在，但已经退到兼容投影和辅助观察层，不再适合作为“内生驱动本体”的解释中心。`task_type_priors` 仍作为内部评分/对齐材料存在，但已不再作为 prompt-facing 独立块进入 LM payload，最新 LM generation context 也不再输出顶层 `task_shape_hint` 或 `raw_candidate_kinds` 候选调试残留。任务形态辅助提示只保留在 prompt 的 `decision_core.secondary_task_shape_hint/score` 中。`attention_agenda.entries` 与 `governance` 顶层也已去掉重复候选计数字段，只保留主议程/主治理所需的信息；`meta_governance` 不再输出重复 `entries`，只保留治理姿态和轻量 context 指针。

这意味着当前系统已经不再是“高级任务生成器”主线。

### 2.3 关键行为边界已经补齐一大批

当前已经稳定收住的，不需要再当开放问题继续挂着：

- 弱证据场景下允许正确地“不行动”
- `need -> intent -> signal -> candidate` 的主链对齐明显改善
- `primary_need / primary_intent / preferred_focus` 不再轻易被 append 顺序或旧兼容字段反向接管
- `historical_underdelivery`、恢复、recent relapse、observation-first 这一组边界已经比前期稳定很多
- observation 模式下不会再靠兜底逻辑把 learning / memory 候选偷偷复活
- truthfulness / queue review 的阈值、保留和 tie-break 已有实质回归保护
- 监督者 UI 已改为读取 wrapped cognition state 内的薄 `lm_trace`，不再依赖旧 `lm_reasoning_state` 大包
- outcome 写回幂等检查已覆盖完整保留窗口，避免同一 task/status/event 在长链运行后重复放大 strategy memory 计数
- governance events 已按 `event_id` 和未消费同义事件两层去重，避免重复落盘或重复评估生成的新 UUID 双倍推高自调节和 truthfulness 纠偏强度

这些点说明内生驱动已经从“方向经常跑偏”进入“主轴基本稳定”的阶段。

### 2.4 第一批长链稳定性证明已经建立

最近已经补上并验证了第一批真正有价值的跨轮回放：

- continuity / memory 多轮写回后，truthfulness 仍可接管
- mixed writeback + context switch 下，没有观察到主轴被旧 focus 慢性锁死
- cleared historical window 下，复合 observation carryover 不再把主轴重新卡回 observation
- 更长链累积后，旧 observation target 不再只会单向积累 `recommended`，开始具备 `resolved` 回补，learning / truthfulness 轴也没有被这类累积直接锁死
- `completed / paused / retry / awaiting_review / deferred / failed` 混合的旧脏历史下，近期连续 self-learning completed 序列可以释放 observation posture，不再被陈旧 underdelivery 永久拖住
- 恢复链之后再次出现 `retry / deferred` 近期 relapse 时，即使 strategy memory 偏向 learning、旧 observation target 已 resolved、旧 self-regulation 已衰减，仍会重新进入 observation 并收紧 candidate budget
- 经过真实 plan/writeback 连续积累的同一批 strategy memory 下，系统可以在“最近 relapse -> observation 收紧”和“最近 completed 链 -> 释放 observation”之间双向切换
- 同一批连续 writeback strategy memory 下，更脏的 planned-only / retry / deferred / completed / failed 混合 history 也可以在“近期 relapse 收紧”和“近期 completed 释放”之间切换；planned-only outcome 不会被当作真实 post-task 效果来放大恢复或复发
- 真实 plan/writeback 产生的 outcome 历史即使被打乱顺序回放，也会按 `recorded_at` 恢复时间窗口，保持 reflection / adaptive policy / primary need 稳定
- 治理事件先被消费、随后 drive 入队阶段失败并回滚、再发生 context switch 重新入队时，已消费的治理事件不会被撤销，失败候选也不会留下 judgement / strategy 污染
- 连续两批治理事件消费、两次 drive plan 失败回滚、两次不同 context 成功重入队后，旧消费时间不倒退，失败候选不进入 judgement / strategy，成功候选按 context 各记录一次

这说明当前最核心的风险，已经不是“主线有没有切过去”，而是“长链、多噪声场景下还能稳定多久、稳定到什么程度”。

## 3. 重新审视后的当前判断

一句话判断：

> 当前内生驱动已经是一个有真实认知主线、可稳定使用的系统；它不再处于“概念分叉”或“随时退回旧任务生成器”的状态。

更具体地说：

- 它已经是智能的：因为主判断链、认知状态和治理输出已经成形，不再只是规则拼任务
- 它已经是可用的：因为关键边界已有大量回归保护，很多早期明显错位已经清掉
- 它还不是完全收口的：因为兼容残留仍偏厚，超长链稳定性证明也还不够充分

所以现在不应继续把问题清单写成“好像整个系统还在大面积失控”的样子。

## 4. 当前还剩的真实问题

这部分只保留当前仍值得继续跟踪的开放问题。

### 问题 1：更长链、更脏序列下的稳定性证明还不够

当前已经有第一批长链回放，但还不够覆盖真实运行中的更复杂情况，例如：

- 更长周期的 `completed / deferred / failed / retry / paused` 混合序列
- `focus_stats / contextual_focus_stats / observation_target_stats` 长时间共同累积后的副作用
- self-regulation 衰减、posture 切换、history 写回交织后的慢性偏移

其中“旧脏历史 + 近期连续完成”的释放路径、“恢复后再次 relapse + 陈旧 strategy memory + 衰减 self-regulation”的重新收紧路径、“连续 strategy writeback 后恢复/relapse 双向切换”的路径、“同一 strategy memory 下 planned-only / retry / deferred / completed / failed 长脏 history 双态回放”的路径、“真实 writeback 历史打乱顺序回放仍按时间窗口稳定”的路径，以及“治理事件消费 + drive 入队失败回滚 + context switch 重入队”的路径已经补上回归；多轮治理事件消费 / 入队失败回滚 / context switch 成功重入队的交织链也已有第一条回归，outcome 重复写回对 strategy memory 的慢性污染、重复 governance event 对纠偏强度的双倍放大、重复评估生成同义未消费治理事件的新 UUID 增殖也都已补上幂等回归。现在最值得继续补的是更长真实时间跨度下，更多上下文和真实 outcome 写回混合后的持续稳定性证明，而不是再回头补大量单轮边界。

### 问题 2：兼容残留仍偏厚

虽然主定义已经前移，但内部仍保留较多旧范式残留，例如：

- 内部 `task_type_priors` 评分/对齐材料
- 偏 candidate-centric 的部分 scoring / trimming / merge 逻辑

其中任务形态辅助提示已从 runtime `proposal_cognition.meta_cognition_profile` 和 `priority_signals` 中降下去，只保留在 LM prompt 的 `decision_core.secondary_task_shape_hint/score` 内作为二级辅助提示；`task_type_priors` 也已从 prompt-facing 独立块和最新 LM 状态快照中撤下。后续不应再把它们恢复成前台主判断字段。

这部分的风险不是当前行为立刻出错，而是后续新会话、新修改容易顺着旧骨架继续长，把系统重新拖回“候选任务中心制”。

### 问题 3：`proposal_cognition` 仍然偏厚

`proposal_cognition` 现在已经降级成辅助观察层，这是对的；并且 `proposal_drift_memory`、`self_iteration_*`、`switch_*`、`post_task_effect_*`、`cognitive_assessment_memory` 这批运行态辅助记忆已经折进 `auxiliary_memory`，前台只保留状态/方向/质量均值/计数，不再和 posture / assessment trace 并排，也不再暴露 common_* 历史文本列表。LM prompt 与最新 LM generation context 内的 `cognitive_assessment_memory` / `self_iteration_trend_memory` 也已改成 dominant 文本 + signal count + summary，`self_iteration_hypotheses` 改成 dominant/count/top evidence，不再展开 common_* 或 hypotheses 明细列表；最新 LM generation context 现在会优先读取这些薄字段，旧 `common_*` 只作为兼容 fallback，避免削薄后反而丢失纠偏计数。`proposal_cognition` 的 self-iteration hypotheses fallback 也不再临时生成旧式 `hypotheses` 列表，而是直接生成 dominant/count 薄字段，薄字段 `why_not_improvement_now` 也会直接进入 self-iteration hypotheses，不再依赖旧 `common_why_not_improvement_now`；`cognitive_assessment_memory` 与 `self_iteration_trend_memory` 的 engine/runtime 源头也已经直接产 dominant + unique signal count + entry_count，不再先构造 `entries/common_*` 后再压薄；prompt compact helper 也优先读取薄计数字段，旧 `common_*` 仅保留 legacy fallback，避免削薄后的 prompt 计数归零；`self_iteration_hypotheses` 的 prompt compact 和最新 LM context 也优先使用薄 `hypothesis_count/suggested_task_types/top_priority`，旧 `hypotheses` 明细只补空，不再用旧明细长度放大纠偏权重；engine `post_task_effect_memory` 也已对齐 runtime，跳过 planned-only outcome，只保留效果均值、方向、主 effect 和 entry_count。旧快照中的 `common_*` 单字符串 fallback 现在按完整文本读取，不再被拆成字符参与 dominant 或 count。`recent_reference_alignment` 与 `recent_cognitive_alignment` 前台也已改成 signal/missing/entry 计数和主缺口/主形态，不再展开候选反馈历史；`recent_reference_alignment` 的源头现在也直接产 `entry_count / primary_missing_* / missing_*_count`，`proposal_drift_memory` 与 `recent_cognitive_alignment` 的源头也改为直接累积 score/count/signals，不再先构造临时 entry 明细；旧 `recent_entries` 只作为 prompt/attention helper 的 fallback，且不再和薄字段叠加 weak/partial 计数；`current_candidates` 也只保留数量、LM 生成数量和平均 alignment 分数，不再展开候选条目、`task_type_counts` 或 `quality_counts`。

它仍然偏厚，主要风险已经从“明显并列主结构”下降为“辅助包未来被继续加字段、后续修改容易重新展开”。

这不是高危功能问题，但确实还是当前 runtime 表达层里最容易继续长歪的一块。

### 问题 4：任务候选相关实现体量仍然过大

从架构语义上，任务候选已经是兼容投影；但从代码体量和实现重心上看，它仍然占了明显更大的篇幅。

这会带来一个实际风险：

- 后续开发很容易继续沿 candidate 逻辑修修补补
- 反而让真正的认知判断链再次退回幕后

所以这不是“功能错误”，而是“实现重心还没完全跟语义重心对齐”。

## 5. 已清出的已处理问题

以下类型的问题，当前不再作为开放问题继续挂在本清单里：

- 文档层双主线分叉
- LM 提示词设计与主设计分家
- 弱证据下硬凑任务
- `primary_need / primary_intent / preferred_focus` 被旧排序或旧字段轻易带偏
- `historical_underdelivery` 与恢复、recent relapse、observation-first 的主要边界错位
- observation 模式下 learning / memory fallback 被兜底逻辑复活
- 第一批多轮 continuity / memory / mixed writeback 场景下的主轴接管问题

这些内容已经变成“已收敛成果”，不再适合继续堆成开放清单。

## 6. 最新优先级

### P0：继续补超长链稳定性回归

优先补的不是更多定义，而是更长、更脏、更贴近真实运行的序列稳定性验证。

重点继续盯：

- `judgement_core.primary_need`
- `primary_intent`
- `preferred_focus`
- observation gate / review gate
- candidate budget / learning quota

### P1：继续削薄兼容层

重点不是再造新名词，而是继续压低旧兼容骨架的存在感：

- 继续维持 `proposal_cognition.auxiliary_memory`、`proposal_drift_memory`、`recent_cognitive_alignment`、`current_candidates` 的状态/计数口径，避免辅助包重新展开成并列主结构
- 继续只在内部 evidence/scoring 中使用 `task_type_priors`，不要恢复成 prompt-facing 独立块或最新 LM 状态整块
- 继续确保 `secondary_task_shape_hint/score` 只作为 `decision_core`/prompt 内二级提示，不回到 runtime 前台主 profile，也不从旧 `meta_cognition_profile` 输入回流
- 压重复摘要和重复解释层

### P2：最后再做接口命名收口

等稳定性和内部厚度再扎实一点，再处理这些名字会更顺：

- `evaluate_endogenous_drive()`
- `EndogenousTaskCandidate`
- `proposal_cognition`

这一步应该是最后收口，不应该重新变成主战场。

## 7. 当前不建议继续做的事

现阶段不建议继续把清单往这几个方向无限延伸：

- 再把每个已解决边界单独保留成长期开放条目
- 再扩一套新的认知术语层
- 为了“看起来更完整”继续往 runtime 前台加说明字段
- 在稳定性证明还没继续补足前，就大规模改接口名和对象层级

## 8. 一句话结论

当前内生驱动已经从“是否摆脱旧任务生成器”这个阶段毕业了。

现在更准确的状态是：

> 主线已经稳定收敛到“认知判断 + 治理输出选择”；当前剩下的真实问题，主要是兼容残留仍偏厚，以及超长链稳定性证明还不够。

所以这份问题清单也应该同步收口：只保留仍然真实存在的问题，不再把已经处理完的边界无限累积成第二份历史档案。
