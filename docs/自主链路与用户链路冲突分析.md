# 自主链路与用户链路冲突分析

> 当前实现基线：2026-08-08。本文只描述现行架构，不保留已删除的完整后台 CLI 路径。

## 1. Owner 与边界

| Owner | 负责 | 不负责 |
| --- | --- | --- |
| 父 `VoidcubeCLI` | prompt-toolkit TUI、用户输入、命令路由、父事件投影 | 自主 Agent 的执行状态 |
| `AutonomousExecutionHost` | 自主 session/history、Agent、任务状态、pending queue、工具事件端口 | `run`、`chat`、TUI、keybinding、voice |
| `TurnScheduler` | 活动 turn、队列、lane、优先级、门控和取消 | Agent turn-local 状态与终端渲染 |
| `CliAgentTurnExecutorRuntime` | 在显式 owner 上执行一个 Agent turn | 调度决策、TUI 和快捷键 |

自主链路和 scheduled-task 都不再通过 `type(self)(...)` 创建第二个完整 CLI。
二者分别由窄的 execution owner 持有，不能把展示层能力复制到后台执行域。

## 2. 执行路径

```text
Supervisor approved task
  -> AutonomousExecutionHost pending queue
  -> TurnScheduler.submit_autonomous()
  -> CliAgentTurnExecutorRuntime.execute(supervisor_task)
  -> owner history/session + parent panel event projector
```

父 CLI 的普通输入始终提交为 `user_chat`。两条 lane 共用一个 Scheduler，因此同一时刻
最多一个模型 turn；用户 turn 优先，自主 turn 在用户执行期间排队。session、history、
tool policy 和执行状态彼此隔离。

## 3. 状态与事件

- 调度状态只能从 `SchedulerSnapshot` 读取，不能通过另一个 host 的私有字段推断。
- 父 TUI 读取 `AutonomousExecutionSnapshot` 展示自主任务、spinner、队列和执行结果。
- 自主工具事件通过父 panel event ports 投影到展示层，不写入用户 history。
- Agent 只由对应 execution owner 持有；owner 没有 prompt、keybinding 或 voice API。

## 4. 命令语义

业务控制只走显式命令：

| 命令 | 作用 |
| --- | --- |
| `/cancel` | 取消当前 `user_chat` turn，幂等并发布取消事件 |
| `/auto` | 开启 autonomous gate 并启动自主轮询 |
| `/auto-q` | 关闭 autonomous gate 并请求取消自主 turn |
| `/quit` | 退出 CLI |

普通输入不承担取消或退出语义；取消失败、超时和 Agent 已退出都必须产生结构化事件。
