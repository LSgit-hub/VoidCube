# 自主进化候选生成与可信执行计划

> 文档状态：规划中
>
> 创建日期：2026-08-14
>
> 关联文档：[自主学习架构改进方案.md](自主学习架构改进方案.md)、[自检查报告.md](自检查报告.md)

## 1. 目标

补齐自主进化链路中尚未实现的候选生成阶段：让 Agent 在隔离 worktree 和可证明的项目执行环境中完成代码修改、测试、提交候选 commit，并把结果交给现有的 BenchmarkPack、ExperimentResult、Governor 和用户同意流程。

目标链路：

```text
认知缺口
  -> 改进假设
  -> 隔离 worktree
  -> Agent 编码
  -> 同一执行环境测试
  -> candidate commit
  -> baseline/candidate 对比评测
  -> ExperimentResult
  -> Governor
  -> 用户同意
  -> 身体切换
```

## 2. 已有基础和边界

以下能力已完成，本计划不重复实现：

- `SelfCognitionSnapshot`、`KnowledgeArtifact`、`BenchmarkPack`、`ExperimentSpec`、`ExperimentResult` 的不可变存储和引用校验。
- baseline/candidate 评测环境清单、平台硬门和容器失败不得本地回退。
- `ExperimentResult -> Governor -> probe -> 用户同意 -> 身体切换` 的治理闭环。
- `body_improvement` 只消费已经评测的候选提交，不现场编辑文件或创建提交。

必须保持的边界：

- 没有匹配的项目执行环境时，任务为 `blocked`，不得声称测试通过。
- Podman/WSL 结果不能冒充 Windows 宿主验证结果。
- Agent 不能自行填写测试结果、评分、环境身份或晋升结论。
- 候选代码必须通过允许路径、提交绑定、测试和治理硬门后才能进入正式身体。

## 3. 阶段计划

### 第 5A 阶段：环境身份与检出证据拆分

状态：`pending`

目的：允许在同一个执行环境中依次 checkout baseline 和 candidate，同时不把 Git HEAD 变化误判为环境漂移。

工作项：

- [ ] 新增 `ExecutionEnvironmentIdentity`，只包含平台、工具链、依赖指纹、路径映射和执行后端。
- [ ] 新增 `SubjectCheckoutEvidence`，记录 baseline/candidate HEAD、worktree 和 checkout 时间。
- [ ] 保留现有 `ExecutionEnvironmentManifest` 的不可变内容寻址和兼容读取边界。
- [ ] 更新 `ExperimentSpec`、评测执行器、报告和治理校验，分别引用环境身份与 checkout 证据。
- [ ] 增加 baseline/candidate 同环境不同 HEAD 的回归测试。

完成条件：切换 baseline/candidate commit 不产生环境漂移；不同 OS、工具链或依赖指纹仍然被拒绝。

### 第 5B 阶段：项目执行器契约

状态：`pending`

目的：统一 Windows 宿主和 Podman 执行器的生命周期、路径和能力报告。

工作项：

- [ ] 定义 `ExecutionBackend`、任务级 `task_id` 绑定和执行器状态机。
- [ ] 定义工作区、允许路径、环境变量、超时、输出上限和进程清理契约。
- [ ] 定义 `probe`：Git、Python、pytest、Node、npm、项目依赖和路径映射必须可验证。
- [ ] 缺少依赖、平台不匹配、Podman 启动失败统一返回结构化 `blocked`，禁止本地隐式回退。
- [ ] 让 file tools 和 terminal tools 使用同一个执行器和同一个 task scope。

完成条件：同一任务的读写和命令执行始终落在同一个 worktree/执行环境；所有能力均来自探针证据。

### 第 5C 阶段：Windows 宿主执行器

状态：`pending`

目的：为当前 Windows 项目提供可用于最终晋升的真实验证环境。

工作项：

- [ ] 使用项目 `.venv\\Scripts\\python.exe` 和锁定的项目依赖。
- [ ] 对 Windows 绝对路径、工作目录和子进程启动做规范化，禁止把宿主路径传给容器工具。
- [ ] 采集 Python、pytest、Node、npm、Git 版本和依赖指纹。
- [ ] 支持隔离 linked worktree、超时终止、残留进程清理和结果持久化。
- [ ] 增加 Windows 专属执行器契约测试。

完成条件：生成 `validation_scope=host` 且 `validated_platforms=("windows",)` 的可审计执行证据。

### 第 5D 阶段：完整 Podman 项目镜像

状态：`pending`

目的：提供可复现的 Linux 容器预检环境，不把它误认为 Windows 最终验证。

工作项：

- [ ] 从当前基础运行时升级为包含项目依赖、pytest 和必要 Node 依赖的版本化镜像。
- [ ] 镜像构建使用项目声明和锁文件，记录镜像 digest。
- [ ] 将项目 worktree 映射到固定 `/workspace`，阻止访问工作区外的宿主路径。
- [ ] 明确容器验证的 `validation_scope=container` 和 `validated_platforms=("linux",)`。
- [ ] 增加镜像缺依赖、启动失败和路径映射失败测试。

完成条件：Podman 可以独立执行项目预检；任何容器证据都不会绕过 Windows 平台硬门。

### 第 5E 阶段：`EvolutionAuthoringExecutor` 候选生成器

状态：`pending`

目的：让 Agent 在授权范围内完成一次可审计的候选修改。

工作项：

- [ ] 从 baseline commit 创建一次性隔离 worktree。
- [ ] 向 Agent 提供目标、改进假设、允许路径、执行环境能力和停止条件。
- [ ] 通过 task scope 绑定文件读取、补丁写入、终端命令和日志。
- [ ] 禁止修改工作区外文件、伪造测试结果、修改评测证据和直接触发晋升。
- [ ] 要求工作区干净后创建 candidate commit，并记录完整 Git SHA。
- [ ] 没有变更、测试失败、超时、环境阻塞或越权写入时，生成结构化失败结果而非候选提交。

完成条件：候选生成器只产出“候选提交 + 执行证据”，不直接改变正式身体。

### 第 5F 阶段：接入现有评测和治理链路

状态：`pending`

工作项：

- [ ] 用生成的 candidate commit 创建 `ExperimentSpec`。
- [ ] 在同一个 `ExecutionEnvironmentIdentity` 下分别 checkout baseline/candidate 并运行固定 BenchmarkPack。
- [ ] 将每条命令、退出码、日志摘要、checkout 证据和环境清单 ID 写入实验证据。
- [ ] 复用现有 hard gates、`ExperimentResult`、Governor、probe 和用户同意流程。
- [ ] 删除或禁止任何绕过候选生成器、评测提交绑定或平台硬门的旧入口。

完成条件：从认知缺口到用户同意形成一条可回放、可拒绝、不可伪造的完整链路。

### 第 5G 阶段：端到端验证和文档收口

状态：`pending`

- [ ] 增加无环境、依赖缺失、Podman 失败、Windows 验证、平台不匹配和测试失败场景。
- [ ] 增加候选越权修改、伪造 HEAD、证据篡改和重复执行场景。
- [ ] 使用项目虚拟环境运行定向测试、Smoke、完整测试、退役集成扫描和 wheel 契约。
- [ ] 更新自检查报告、全链路问题清单和项目说明书中的真实状态。
- [ ] 记录每阶段完成日期、测试命令和未解决风险。

完成条件：所有自动晋升路径都有环境证据和测试覆盖；文档状态与实际代码一致。

## 4. 推荐实施顺序

严格按 `5A -> 5B -> 5C -> 5D -> 5E -> 5F -> 5G` 执行。

先完成环境契约和 Windows 执行器，再让 Agent 获得写入能力。候选生成器接入前，现有评测和身体改进链路继续保持只消费外部候选提交的行为。

## 5. 阶段记录模板

每完成一个阶段，必须补充：

- 实际完成日期和变更文件。
- 使用的执行环境及 `environment_id`。
- 定向测试、完整测试和退役扫描结果。
- 新增的拒绝/阻塞边界。
- 尚未解决的风险和下一阶段入口。
