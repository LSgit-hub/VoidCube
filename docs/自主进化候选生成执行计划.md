# 自主进化候选生成与可信执行计划

> 文档状态：规划中

## 1. 目标

补齐自主进化链路中尚未实现的候选生成阶段：让 Agent 在隔离 worktree 和可证明的项目执行环境中完成代码修改、测试、提交候选 commit，并把结果交给现有的 BenchmarkPack、ExperimentResult、Governor 和用户同意流程。

目标链路：

```text
认知缺口
  -> 改进假设
  -> 隔离 worktree
  -> Agent 编码
  -> 同一执行环境测试
  -> candidate commit
  -> baseline/candidate 对比评测
  -> ExperimentResult
  -> Governor
  -> 用户同意
  -> 身体切换
```

## 2. 已有基础和边界

以下能力已完成，本计划不重复实现：

- `SelfCognitionSnapshot`、`KnowledgeArtifact`、`BenchmarkPack`、`ExperimentSpec`、`ExperimentResult` 的不可变存储和引用校验。
- baseline/candidate 评测环境清单、平台硬门和容器失败不得本地回退。
- `ExperimentResult -> Governor -> probe -> 用户同意 -> 身体切换` 的治理闭环。
- `body_improvement` 只消费已经评测的候选提交，不现场编辑文件或创建提交。

必须保持的边界：

- 没有匹配的项目执行环境时，任务为 `blocked`，不得声称测试通过。
- Podman/WSL 结果不能冒充 Windows 宿主验证结果。
- Agent 不能自行填写测试结果、评分、环境身份或晋升结论。
- 候选代码必须通过允许路径、提交绑定、测试和治理硬门后才能进入正式身体。

### 第 5K 阶段：版本化环境能力治理策略

状态：`completed`（2026-08-15）

目的：把 Tirith 扫描器和容器磁盘 quota 从无差别告警升级为内容寻址、按部署 profile 生效且进入任务授权绑定的治理策略，避免临时开发环境缺能力阻断开发，也避免生产环境带着已知能力缺口晋升。

工作项：

- [x] 新增不可变 `EnvironmentCapabilityPolicy`，policy version、profile、允许状态和内容哈希共同生成稳定 policy ID。

- [x] Governor 对 authoring 和 validation 分阶段评估 capability，失败返回 phase、capability、status 和 reason code。
- [x] authorization、候选约束、任务 evidence 和最终 body review 精确绑定 policy ID/version/profile、状态、告警和违规集合。

- [x] 新增 `supervisor.service_runtime.evolution_capability_policy_profile` 与 `SUPERVISOR_EVOLUTION_CAPABILITY_POLICY_PROFILE`；非法配置在加载时拒绝。

策略语义：

- `development`：所有已知 capability 状态均可继续，但非理想状态保留明确告警。
- `ci`：authoring 与 validation 的扫描器都必须为 `available`；磁盘 quota 非理想状态只告警。
- `production`：扫描器必须为 `available`；磁盘 quota 只允许 `enforced` 或 Windows 等非容器场景的 `not_applicable`。
- 旧实验记录仍可读取；缺 capability 证据不能重新授权，旧 body task 缺 policy binding 不能进入新的执行主路径。
- 默认 profile 为 `development`。生产部署必须显式配置 `production`，不得仅凭运行位置猜测部署等级。
