# 自主进化候选生成与可信执行计划

## 1. 目标

补齐自主进化链路中尚未实现的候选生成阶段：让 Agent 在隔离 worktree 和可证明的项目执行环境中完成代码修改、测试、提交候选 commit，并把结果交给现有的 BenchmarkPack、ExperimentResult、Governor 和用户同意流程。

目标链路：

```text
认知缺口
  -> 改进假设
  -> 隔离 worktree
  -> Agent 编码
  -> 同一执行环境测试
  -> candidate commit
  -> baseline/candidate 对比评测
  -> ExperimentResult
  -> Governor
  -> 用户同意
  -> 身体切换
```

## 2. 已有基础和边界

以下能力已完成，本计划不重复实现：

- `SelfCognitionSnapshot`、`KnowledgeArtifact`、`BenchmarkPack`、`ExperimentSpec`、`ExperimentResult` 的不可变存储和引用校验。
- baseline/candidate 评测环境清单、平台硬门和容器失败不得本地回退。
- `ExperimentResult -> Governor -> probe -> 用户同意 -> 身体切换` 的治理闭环。
- `body_improvement` 只消费已经评测的候选提交，不现场编辑文件或创建提交。

必须保持的边界：

- 没有匹配的项目执行环境时，任务为 `blocked`，不得声称测试通过。
- Podman/WSL 结果不能冒充 Windows 宿主验证结果。
- Agent 不能自行填写测试结果、评分、环境身份或晋升结论。
- 候选代码必须通过允许路径、提交绑定、测试和治理硬门后才能进入正式身体。

### 第 5E 阶段：`EvolutionAuthoringExecutor` 候选生成器

状态：`completed`（2026-08-14）

目的：让 Agent 在授权范围内完成一次可审计的候选修改。

工作项：

- [x] 从 baseline commit 创建一次性隔离 worktree。
- [x] 向 Agent 提供目标、改进假设、允许路径、执行环境能力和停止条件。
- [x] 通过 task scope 绑定文件读取、补丁写入、终端命令和日志。
- [x] 禁止修改工作区外文件、伪造测试结果、修改评测证据和直接触发晋升。
- [x] 要求工作区干净后创建 candidate commit，并记录完整 Git SHA。
- [x] 没有变更、测试失败、超时、环境阻塞或越权写入时，生成结构化失败结果而非候选提交。

完成条件：候选生成器只产出“候选提交 + 执行证据”，不直接改变正式身体。

阶段记录：

- 新增不可变、内容寻址的 `EvolutionAuthoringSpec`、`EvolutionAuthoringContext` 和 `EvolutionAuthoringResult`，成功结果必须同时绑定 candidate commit/ref、变更文件和环境身份证据；失败结果不能发布候选。
- 执行器独占一次性 detached linked worktree、严格 task scope、测试命令、Git 提交和候选 ref 发布；Agent 只能在 `/workspace` 内按路径授权修改，不能自行提交或改写 Git refs。
- Agent 返回后和提交前均以真实 Git 状态执行全局 evolution boundary、任务路径、禁止模式和文件数检查；无变更、越权、测试失败、环境阻塞和提交失败均返回结构化拒绝结果。
- file-tools 重建任务容器时继续继承 `container_persistent=False` 和 `docker_mount_host_integrations=False`；候选任务的命令超时进入同一个严格执行契约。
- 真实 Podman 探针通过 `/workspace` 的 `read_file_tool`、`write_file_tool` 修改一次性候选，容器内运行 `python -m py_compile` 后生成候选提交 `fb1c9ffd334607305b86936112c82df23663061d`；探针 ref 随后被精确删除，主工作树未发生变化。
- 探针环境清单 ID 为 `execution-environment-e6df4d277a1a0c9e9ae38d3e9f47d9780833a64b909db63bdf7e7c63870ecddd`，环境身份 ID 为 `execution-environment-identity-6f3bd66ae14d734b85e6cd95fb6bc62cb5e761fe659e549d3b3d1df2a7e84a44`。
- authoring、环境、评测、治理、边界、task scope、打包和退役集成定向回归共 `111 passed`；Ruff 和 `git diff --check` 通过；真实 wheel 构建及来源契约验证通过。

## 4. 推荐实施顺序

严格按 `5A -> 5B -> 5C -> 5D -> 5E -> 5F -> 5G` 执行。

先完成环境契约和 Windows 执行器，再让 Agent 获得写入能力。候选生成器接入前，现有评测和身体改进链路继续保持只消费外部候选提交的行为。
