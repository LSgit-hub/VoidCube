# VoidCube 桌面前端设计

状态：已实现第一版
实现目录：`desktop/`

```text
┌──────────────────────────────┐  Electron 主窗口
│ 上半区 Supervisor iframe     │  http://127.0.0.1:6002/ui
├──────── 可拖动分割条 ────────┤
│ 下半区 xterm.js              │  node-pty -> Python 3.14 -> voidcube CLI
└──────────────────────────────┘
```

## 技术决定

- Electron + TypeScript：窗口、进程生命周期和跨平台打包。
- xterm.js：终端渲染、ANSI、中文输入和尺寸同步。
- node-pty：Windows ConPTY 与 macOS/Linux PTY，不使用普通管道模拟终端。
- 原有 FastAPI Supervisor 页面继续独立运行，桌面端不复制监控状态协议。
- vanilla Vite 渲染层：容器界面较薄，不引入不必要的组件框架。

## 进程与安全边界

Electron 主进程负责解析 Python、创建 PTY、探测 Supervisor 和回收 CLI。preload 只暴露受限终端与监控接口；渲染进程启用沙箱和上下文隔离，不能直接访问 Node。Supervisor iframe 仅接受本机回环 HTTP 地址，并禁止顶层导航。

`voidcube.py` 仍是唯一 Python 入口，由它启动 Gateway、Memory 和 Supervisor。桌面端只观察 `/ui` 就绪状态，不维护第二套服务编排。

## 当前交互

- 上下区域可由鼠标拖动或分隔条方向键调整，高度保存在本地。
- 工具栏显示监控与 CLI 的独立连接状态。
- 支持重新加载 Supervisor 页面和重启 CLI PTY。
- 服务启动中、页面失败、PTY 启动失败和 CLI 退出都有明确状态。
- 关闭桌面窗口时先向 CLI 请求正常退出，超时后回收 PTY。

## 发行边界

桌面安装包与 Python Agent 保持独立。开发态自动使用仓库 `.venv`；已安装环境可通过 `VOIDCUBE_DESKTOP_PYTHON` 指定 Python。正式离线发行可在后续 CI 中加入 Python 与 VoidCube sidecar，各操作系统分别构建，不能共享一个通用安装包。
