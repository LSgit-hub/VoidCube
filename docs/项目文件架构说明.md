# VoidCube 项目文件架构

更新日期：2026-07-21

## 1. 入口与启动关系

对外命令 `voidcube` 和 `vc` 都指向 `voidcube.py:main`。标准交互路径是：

```text
voidcube.py
  -> 确保 Gateway / Memory / Supervisor 可用
  -> VoidCube_cli/main.py
    -> cli.py
      -> run_agent.py
```

四个入口文件不是四套实现：

| 文件 | 所有权 |
| --- | --- |
| `voidcube.py` | 统一安装入口和守护服务引导 |
| `VoidCube_cli/main.py` | CLI 参数、子命令和交互入口分发 |
| `cli.py` | prompt_toolkit 会话、用户交互和自主链路薄桥接 |
| `run_agent.py` | API-A Agent 主循环、工具调用和会话编排 |

## 2. 顶层目录

```text
VoidCube/
├─ VoidCube_core/       底层常量、路径、日志、状态和时间
├─ VoidCube_cli/        CLI 命令、配置、UI、附件、自主执行组件
├─ agent/               请求/响应、上下文、调度、记忆和展示能力
├─ tools/               工具注册、执行后端、安全和外部能力
├─ systems/             Gateway、Memory、Supervisor、Execution
├─ Mem/                 独立 MemAI 领域包、测试、基准与设计规范
├─ plugins/             运行时插件入口
├─ skills/              可加载技能
├─ presets/             运维预设
├─ scripts/             构建与隔离安装验证
├─ tests/               主仓回归测试
├─ containers/          默认运行镜像
├─ docs/                现役架构与工程说明
├─ voidcube.py          安装入口
├─ cli.py               交互会话入口
├─ run_agent.py         Agent 主编排器
└─ pyproject.toml       依赖、打包与 console scripts
```

## 3. 目录所有权

### `VoidCube_core/`

只放无业务偏好的共享底层能力。调用方从具体子模块导入，不通过根包重导出：

- `constants.py`：`VOIDCUBE_HOME`、配置、缓存和状态路径。
- `logging.py`：日志初始化。
- `state.py`：通用状态读写。
- `time.py`：时区感知时间。
- `utils.py`：低层通用函数。

### `VoidCube_cli/`

拥有用户界面和本地 CLI 生命周期：

- `main.py`：命令入口。
- `config.py` / `config_commands.py`：配置数据层与命令展示层。
- `api_config.py` / `auth.py` / `credential_manager.py`：现役 Provider 与凭据配置。
- `attachments.py`：本地附件、拖放路径和图像输入。
- `chat_render_state.py`：流式文本、推理框、预过滤缓冲和用户回合级展示标记的唯一状态所有者。
- `chat_stream_processor.py`：推理标签过滤、有序 text/reasoning 分段、preview 分块和文本/推理行缓冲的纯转换所有者。
- `chat_stream_renderer.py`：终端响应/推理框、皮肤颜色、preview 展示、延迟正文和 flush 输出顺序的唯一协调者。
- `command_router.py`：slash/path 判定、命令解析、中央 alias 规范化、慢命令状态和动态命令优先级/前缀决策。
- `command_execution.py`：内建命令 spec 表、原参数传递、退出结果以及 busy 状态的进入、嵌套恢复和异常收尾。
- `autonomous_gate.py`：`/auto`、`/auto-q` 与 Supervisor gate 的唯一 CLI 桥接。
- `autonomous_runtime_host.py` / `autonomous_executor.py`：内嵌 API-A 自主执行组件。
- `autonomous_panel.py` / `autonomous_observation.py`：按需展示自主链路状态。

`/auto` 会启用 Supervisor 周期任务和内嵌执行组件；`/auto-q` 会停用二者。主 CLI 的用户输入始终保持可用。

### `agent/`

拥有可从 `run_agent.py` 逐步抽离的 Agent 内部能力：

- `api_request.py`：API-only 消息副本、临时上下文注入、内部字段隔离、工具消息修复和 Chat Completions 请求参数。
- `api_response.py`：Chat Completions 响应检查、规范化和截断恢复决策。
- `api_attempt.py`：单次模型调用的 retry、恢复、重启标记和请求/响应快照。
- `response_disposition.py`：兼容 content 规范化、工具名/JSON 检查、文本/空响应判定，以及验证失败和文本 action 应用。
- `error_classifier.py` / `retry_utils.py`：错误分类、重试决策、fallback/transport 执行顺序和可中断等待。
- `context_compressor.py` / `context_engine.py`：上下文预算、压缩算法和统一 payload/context recovery 执行结果。
- `tool_schema.py` / `tool_scheduler.py`：工具 schema 与调度。
- `memory_manager.py` / `memory_provider.py`：Agent 侧记忆接入。
- `session_persistence.py`：会话 JSON、SQLite 增量游标和持久化消息还原。
- `client_lifecycle.py`：共享/请求级客户端、连接替换、关闭和死 socket 清理。
- `chat_transport.py`：请求线程、超时、流式健康检测/重连、非流式降级和中断关闭。
- `conversation_turn.py`：一次用户请求内的调用计数、终态、截断续写、压缩重试和退出原因。
- `turn_finalization.py`：资源清理、持久化、退出诊断、结果快照、hook、外部记忆同步和后台 review 的唯一收尾顺序。
- `stream_response.py`：流式 chunk 的文本、推理、工具调用、usage 与结束原因装配。
- `tool_execution.py`：工具调用规格、顺序/并发调度、计时、异常结果和中断补位。
- `tool_turn.py`：成功工具 turn 的 housekeeping、prefill、执行、上下文压力/压缩与增量持久化顺序，并拥有跨实例 pressure 去重。
- `integration_policy.py`：项目退役集成的统一拒绝策略。

`agent/__init__.py` 只保留无副作用命名空间，不重导出已经失效的初始化 API。新逻辑应优先进入职责明确的模块，不能继续扩大 `run_agent.py`。

### `tools/`

拥有工具注册、权限边界和具体执行能力：

- `registry.py` / `toolsets.py` / `model_tools.py`：发现、schema 和分发。
- `terminal_tool.py` / `file_tools.py` / `browser_tool.py`：主要执行工具。
- `environments/`：local、Docker、SSH、Modal、Singularity、Daytona 后端。
- `skills_tool.py` / `skills_guard.py` / `skill_manager_tool.py`：技能加载与安全扫描。
- `delegate_tool.py`：子代理委派。

### `systems/`

服务化母体的实现目录：

- `gateway/`：服务注册、标准路由、活动事实和双泳道状态。
- `memory/`：Tier 1 会话存储、Tier 2 桥接、查询与维护 API。
- `supervisor/`：内生驱动、治理在途存储、状态机、UI 读模型和 gate 周期任务。
- `execution/`：身体生命周期、probe、切换、回滚和 Gateway executor 路由。
- `body_registry.py` / `lifecycle.py` / `governor.py`：跨服务身体治理核心。

Supervisor 进程同时挂载 Execution Service，但职责仍分开：Supervisor 判断，Execution 执行机械流程。

### `Mem/`

独立可测试的 MemAI 领域包：

- `src/memai/`：Event、Scene、Arc、Epoch、查询、维护和治理事件。
- `tests/`：子项目测试，需显式运行 `python -m pytest Mem/tests -q`。
- `benchmarks/`：记忆质量与 Provider 合同基准。
- `docs/`：MemAI 领域规范，不重新定义 VoidCube 服务拓扑。

## 4. 关键调用链

### 用户调用

```text
cli.py
  -> run_agent.AIAgent
  -> agent.api_request
  -> OpenAI-compatible chat.completions
  -> tools registry / scheduler
  -> agent.api_response
  -> CLI
```

### 自主调用

```text
/auto
  -> VoidCube_cli/autonomous_gate.py
  -> Supervisor /autonomous-chain-gate/activate
  -> endogenous drive + review
  -> AutonomousChainStore
  -> embedded API-A executor polls Gateway tasks
  -> result and memory writeback
```

### 身体切换

```text
body improvement report
  -> Supervisor review and score
  -> Execution candidate/probe
  -> Governor decision
  -> user consent
  -> activate + watch window or rollback
```

## 5. 运行态边界

仓库根目录当前可能出现以下被忽略的本地状态：

- `.body-active.json`、`.body-registry.json`、`.body-slots/`
- `.soul-runtime/`
- `memory.db`、`mem_governance.jsonl`

它们不是源码或可提交样例。当前仍需迁移到 `VOIDCUBE_HOME` 的统一数据目录；迁移完成前不得把这些文件纳入打包或测试夹具。

## 6. 维护热点

| 热点 | 风险 | 修改原则 |
| --- | --- | --- |
| `run_agent.py` | 文件仍大，但当前只作为 Agent 集成 facade 与主循环协调器 | 不再以减行数为目标继续拆分；新行为进入已有职责模块，只有发现新的重复所有权或不可测分支时才继续提取 |
| `cli.py` | 文件仍大，但当前只协调 prompt_toolkit 会话、命令 executor/router 与 Agent 回调 | 不得恢复流式状态机、动态路由或内建分支链；新命令必须同时满足 registry 与 execution spec 契约 |
| `systems/memory/memory_service.py` | 服务 API 与桥接实现体量大 | 先统一 Tier 2 桥接所有权，再拆持久化和路由 |
| `systems/supervisor/planning_runtime.py` | 治理协议和评分规则集中 | 按稳定协议提取，不保留旧字段的长期镜像 |

后续优先级只在 [文档导航](./README.md) 和 [当前问题](./全链路问题清单.md) 维护，本文件不再复制路线。
