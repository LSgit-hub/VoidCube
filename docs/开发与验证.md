# 开发与验证

本文档记录 VoidCube 的本地开发、测试和提交前检查流程。命令均应在仓库根目录执行，并优先使用项目虚拟环境。

## 测试

```powershell
.venv/Scripts/python.exe -m pytest -q
.venv/Scripts/python.exe scripts/run_ci_tests.py
```

涉及技能发现、索引或 registry 的改动，必须额外运行 `pytest tests/test_skill_registry.py`。

### 提交前门禁（必读）

任何 `src/`、`plugins/`、`Mem/src/` 代码改动，提交前必须运行全量门禁：

```powershell
.venv/Scripts/python.exe scripts/run_ci_tests.py
```

它等价于 `pytest tests Mem/tests -q`（带 30 分钟超时）。**不得只跑目标测试文件**。
历史教训：一次只跑目标用例的提交，漏掉了被同批改动破坏的 `tests/test_commands_autocomplete.py`，
回归一直留到下次全量运行才暴露。

## 静态检查与构建

```powershell
.venv/Scripts/ruff.exe check src Mem/src plugins scripts
.venv/Scripts/python.exe -m build
```

## 提交纪律

提交必须路径限定（`git add -- <paths>`），禁止裸 `git add -A` / `git add .`；
提交信息必须描述本次实际改动。禁止把"技能新增"与"产品代码修复"混入同一个提交。
（详见 `AGENTS.md` 第 6 条，由 `.githooks/pre-commit` 守护。）
