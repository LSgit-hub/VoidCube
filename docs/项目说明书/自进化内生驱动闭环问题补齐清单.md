# 自进化内生驱动闭环复核

## 结论

替身 A/B 不是两个独立 Git 仓库，而是同一本体仓库下的两个独立 linked worktree：

```text
本体仓库
  .git/                         共享 Git object store
  src/ tests/                   本体主 worktree
  slots/slot-A/worktree/        替身 A，独立文件与 HEAD
  slots/slot-B/worktree/        替身 B，独立文件与 HEAD
```

A/B 的文件、HEAD、运行时目录和槽位 metadata 独立；Git 对象、提交历史和 refs 的底层存储可以共享。`tests/` 没有被 Git 过滤，当前已跟踪 334 个测试文件；`.test-tmp/`、`.pytest_cache/` 才是忽略项。忽略规则只影响 Git 跟踪和状态，不会让 Python 运行时无法加载测试代码。

## 启动与一致性

`initialize_layout()` 对合法且已物化的 linked worktree 会保留现状；`inspect_layout()` 只读检查 dirty、manifest、HEAD 和 registry pointer，不执行 reset、clean、checkout。启动或健康检查不会自动回滚替身的进化提交。

如果槽位缺失或无法证明物化安全，初始化会抛出 `BodyWorkspaceRecoveryRequired`，拒绝覆盖已有文件。只有明确治理动作才会改变替身内容，例如 `abandon_candidate`、`recycle_retired_slot`、`restore_previous_healthy_commit` 或显式的 `prepare_slot_workspace(clear_existing=True)`。这些动作的 reset/重建属于有意的治理行为，不是普通一致性检查。

因此，“每次启动都初始化”应理解为“每次启动都校验并恢复注册表运行状态”，不是“每次启动都从本体复制一份文件”。合法的进化 HEAD 会被保留；脏目录、HEAD/metadata 不一致或 manifest 损坏会被报告或阻断，不会静默抹掉现场。

## 已接通的自进化闭环

当前链路为：

```text
学习证据
  -> 内生驱动形成 candidate_generation_ready
  -> 幂等登记 EvolutionCandidateGenerationRequest
  -> 生成 candidate commit 并完成评测
  -> Supervisor 将精确 evaluated candidate commit 物化到 shell 槽位
  -> readiness / HEAD / clean / changed files 校验
  -> employee 绑定 BodyRegistry canonical worktree
  -> employee 只检查、验证并提交 JSON 证据
  -> Supervisor review 更新替身健康 metadata
```

已完成的保护包括：

1. candidate request 使用内容寻址，重复内生观察不会产生重复请求；请求只允许指向当前 registry shell 槽位。
2. candidate 物化只允许写入 shell，禁止 active 槽位和 primary worktree；baseline、candidate 祖先关系、评测 changed files、HEAD、clean 和 readiness 都会校验。
3. 物化的 HEAD、metadata 和 manifest 写入具有事务式恢复；写入或 readiness 失败时恢复原 HEAD 和旧 metadata，恢复失败则明确报告 rollback incomplete。
4. employee 不信任 prompt 中的路径，而是从 Supervisor/BodyRegistry 解析 canonical worktree，并通过 `prepare_task_git_worktree()` 使用 Docker/Podman container contract。真实 container environment manifest 由基础设施捕获并注入最终 JSON 回执，employee 不能自报或伪造它。
5. employee 不得编辑文件、创建新 commit、reset 或切换 worktree；完成后再次验证 canonical root、精确 evaluated HEAD 和 clean 状态。环境生命周期结束时释放 task sandbox 和 execution contract。

本体主 worktree 不再要求 HEAD 必须等于 shell baseline；它只需 clean 且能够解析 baseline commit，因为 linked worktree 与本体共享 Git object store。

## 当前边界

candidate generation 和物化的治理主体是 Supervisor；employee 不是候选生成者，也不是候选提交者。employee 只能验证已经评测和物化的 commit。若 Docker/Podman 不可用，body employee 会阻塞并回执失败，不会回退到 local，从而保持 review 所需的 container 语义。
